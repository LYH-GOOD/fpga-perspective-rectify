## Verilog 语言与综合

| # | 坑 | 症状 | 教训 / 对策 |
|---|---|---|---|
| 5 | **Verilog 乘法会静默截断** | 32 位参数 × 12 位坐标，若不加宽会丢高位 | 显式加宽到 48 位再乘（代码里已注释说明） |
| 6 | **统计口径不一致误判为 bug** | Python 报 0.0329、RTL 报 0.0387，看似对不上 | Python 只统计"落在输入图内"的点，TB 统计全部点。加宽 TB 统计后两者完全一致 |
| 7 | **`$clog2` 需要 `-g2005`** | 默认档位下不可用 | `iverilog -g2005`（同时保持源码是纯 Verilog，Vivado 兼容） |
| 8 | **寄存的控制信号会比状态晚一拍** | 输出图整体**错位一个像素** | `row_load`/`advance` 这类"由状态直接决定"的脉冲，**用组合逻辑驱动**（`assign x = (state == S_XXX);`），不要写成寄存输出 |
| 9 | **BRAM 读口：使能和地址必须同拍组合给出** | 四个邻域像素**整体错位一格**，第一个还是陈旧值 | 行的 `rd_en`/`rd_addr` 改成组合驱动；数据在下一拍抓取 |
| 10 | **有延迟的模块，输出也要多等一拍** | 输出比期望**滞后一个像素** | 双线性插值本身有 1 拍寄存延迟，喂完数据后要**多插一个状态**再取结果 |
| 27 | **`integer` 默认是 X，不是 0** | 调试打印静默不输出 | 所有 integer 显式初始化 |
| 28 | **信号声明必须先于使用**（反复踩） | `Could not find variable` | 被 always 块引用的信号，声明提到文件靠前处 |
| 18 | ⭐ **组合逻辑一拍塞太多级 → 时序不收敛** | WNS = -6.878 ns | 乘法+宽加法的链条一经综合就会超周期。**改流水级数必须同步改上层等待状态数** |
| 31 | ⭐ **综合时序过了不等于实现能过** | WNS 从 +0.171 掉到 +0.050 | 必须跑到实现后看 `report_timing_summary`；裕量要看**实现后**的 |
| 98 | ⭐⭐⭐ **子模块内部用了"活输入" → 并行化后随机出错** | 同一组 `(a,b)`，N=1 与 N=8 算出的商差几十 LSB；另一处是"幅值对、符号反"。N=1 时全对 | 顺序除法器里 `q_neg`（符号）在 done 那拍才取、`b_ext`（除数）直接组合进**每次迭代**的比较。N=1 时上游会等 `done`、操作数总线几十拍不动，**侥幸完全正确**；N≥2 后总线每几拍换一次就露馅。**"复用了同一个子模块"只保证算法一样，不保证接口时序无关** —— 并行化一定让子模块输入变不安分。凡"有内部迭代/多拍延迟"的模块，**所有输入必须在启动那拍锁存**，迭代中只认寄存器 |
| 99 | ⭐⭐⭐ **状态标志与真实资源必须【同一个时机】置位** | `busy=0000111` 却 `issued=2`：一个除法器"预定了 busy 但从未启动"，`busy` 永久卡住 | 旧代码在 `do_step` 那拍就"预定"busy，但启动脉冲要 2 拍后才到；行首脉冲在这 2 拍窗口里把 `step_d` 清掉 → 脉冲永不发出 → busy 没人清 → 死锁。**置"忙"这种事不要在"打算用"的时候做，要在"真的开始用"的时候做**。若必须提前占位，就要另设一个**只挡发射、不置状态**的门控，别让状态标志和真实资源解耦 |

## 流式握手与流控

| # | 坑 | 症状 | 教训 / 对策 |
|---|---|---|---|
| 11 | ⭐ **流控的减法会回绕** | 死锁：输入被永久堵死，而它等的那一行永远到不了 | 12 位里写 `(rows_written - y_lo_cur) < ROWS` 会在 `y_lo_cur > rows_written` 时变成大正数。**必须加宽一比特再比较** |
| 12 | ⭐ **"只减不增"的流控下界会锁死** | 前 8 行正常，之后输出全变 `x`（未初始化数据）然后死锁 | `y_lo_cur` 写成 `if (y0 < y_lo_cur) y_lo_cur <= y0` 会**只减不增**，被第 0 行的最小值永久锁住。**每行必须重置**为本行的值 |
| 13 | **边界钳位判据差一** | 右边缘几列像素偏差 4 个灰阶 | 判据应是 `xf >= W_in-1` 而非 `>= W_in-2`：`xf=62`、小数 0.5 时像素 62 和 63 都有效，必须正常插值。**注意这次是 Python 黄金参考错了、RTL 是对的** |
| 17 | ⭐ **改驱动方式时漏删旧赋值 → multi-driven** | 仿真全绿，综合报 70 条 CW | 把一个信号从"寄存驱动"改成"组合驱动"时，**必须同步删除它在复位块/默认分支里的旧赋值**。综合是独立关卡 |
| 23 | ⭐ **AXI：valid 的撤销条件只判 ready** | 握手永远完不成，无报错 | 结束条件必须是「**当前 valid 且 ready**」，不能只判 ready |
| 24 | ⭐ **TB 写 AXI 从机：撤请求/拉 ready/开始轮询必须同拍** | 轮询晚一拍，错过只有 1 拍的 valid | 三件事写在一个 negedge 里 |
| 25 | ⭐ **寄存器映射是字（4 字节）对齐，不是字节对齐** | 参数错位，输出全垃圾但不报错 | 写寄存器前先核对映射表；**用命名常量而不是 `base+1`** |
| 26 | ⭐ **TB 当 AXI-Stream 主机：tvalid 和数据跨拍保持不变** | 每个像素被收两遍，图像被拉伸 | 标准写法是 **tvalid 常高、握手后才换数据** |
| 29 | **"卡住"和"跑错"要用不同探针** | — | 卡住看状态机等什么；跑错看数据通路第一级错在哪 |
| 79 | ⭐⭐⭐ **流式核不能在帧末对上游"关闸"** | DMA 永久挂起，但核的 `busy=0 stuck=0 帧计数=1` | **反压只能"节流"，不能"关闸"**。帧边界/模式切换时必须保证输入仍能被吞掉。视频阶段必踩 |
| 80 | ⭐⭐⭐ **"核空闲 + 有事没干完" = 上游被堵** | 帧计数=1（算完了）却 DMA 超时 | 看到这种组合，直接查**输入/输出握手**，别查核内部 |
| 100 | ⭐⭐⭐ **FIFO 背压必须给【在飞结果】预留槽位** | 慢消费者时 `fifo_cnt=9 > 深度 8`，写指针回卷**压掉未读坐标**；逐像素 dump 与基准差 6200 行 | 发射门控只判 `fifo_cnt >= DEPTH`，但"已经在算、还没算完"的那些结果是**不受门控**地写 FIFO 的 → 深度必须能同时容纳"已排队 + 在飞"。修法：**从阈值里预留 N 个槽位**（`fifo_cnt <= DEPTH - N`，N = 流水线级数）—— 代价只有一次常量比较，不用往关键路径上堆 popcount+加法器。**凡是"上游有多个在飞请求会写同一个 FIFO"的结构，都要算这笔账** |
| 101 | ⭐⭐ **"消费者太快"的 TB 会掩盖背压 bug** | 快速消费时永远测不出 FIFO 溢出；换慢消费者立刻复现 | TB 的默认消费节奏不能比生产快。**测流控必须带一档"慢消费者"**（故意每 N 拍才取一次），否则限流/背压路径等于没测 |

| 137 | ⭐⭐⭐ **"免费"的写法背后往往藏着一个前提，前提一变就静默失效** | 灰度 `ROWS=256`，`row mod ROWS` 写成 `row[7:0]` 位切片，零成本且不可能写错 —— 于是**没人记得这是个特例**。换彩色要 `ROWS=192`（非 2 的幂），位切片就不再等于取模。症状是"画面局部错位、其余正常"，与本项目那个"流控下界取错端"的 bug **长得一模一样** | **凡是"因为某个常量恰好是 2 的幂 / 恰好对齐而免费"的写法，必须在注释里把前提写出来**（本项目已在 `line_buf.v` 里补上）。判据：**问一句"这个常量如果不是 2 的幂呢？"** |
| 140 | ⭐⭐ **TB 里 `always` 块与 `initial` 块共用循环变量 ⇒ 仿真死循环** | `bash run_sim.sh` 卡住不返回，**iverilog 一个错都不报**。根因：`always @(posedge clk)` 的 `for (ci = 0; ci < 3; ci = ci+1)` 每个时钟把 `ci` 重置成 3，而主 `initial` 的 `for (ci = 0; ci < 600; ci = ci+1)` 因此永远长不到 600 | **循环变量是"局部状态"，绝不能跨 `always`/`initial` 复用**。教训推广：Verilog 里所有会被并发块读写的变量都一样（这与 #98"活输入"是同源问题）|
| 141 | ⭐ **iverilog 要求 Verilog-2005 的函数至少有一个输入端口** | `error: Function rnd8 has no ports.` | 无参函数（如 LFSR 取随机数）要加一个用不到的哑元参数，调用时传 0 |
