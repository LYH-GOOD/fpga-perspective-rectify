| 93 | `.gitignore` 规则写死了目录层级，工程一挪位就**静默失效**；`git add -A` 一口气暂存了 641 MB / 4593 个文件 | 忽略规则写成**与层级无关**的（`*.gen/` 而不是 `board/*.gen/`）。建仓后**先看 `git status` 再提交**，别直接 `commit` |
| 94 | `git rm --cached` / `reset` 之后，`.git` 仍有 240 MB（工作区才 35 MB） | `reset` **不会删除已写入的对象**。清孤儿对象：`git gc --prune=now`（本例 240 → 27 MB）。大文件误入后光 reset 不够 |
| 95 | 备份把一个 660 MB 的仓库整份复制走，其中 625 MB 是**可从脚本重建的生成物** | 备份前先做**生成物/成果**的区分（本例真成果只有 35 MB）。为生成物复制副本既浪费磁盘又**制造漂移源** |
| 96 | 被要求"绝对不泄露"，差点直接答"可以保证" | 必须区分**我可控的**（零网络操作、不落同步盘、提交前扫密钥）与**取决于环境的**（机器被物理接触、系统被入侵、用户自己 push）。宁可说"做不到保证"，也不给虚假的安心 |
| 97 | 想开个新目录做下一阶段，第一反应是 `cp -r` | 复制会**再造一个会漂移的副本**。`git init` + tag = 零复制、可回退、可 diff、可只回退单个文件；新阶段开分支即可 |
| 396 | 补丁脚本里写 Windows 路径，写进文件后变成 `D:\AI_Workspaceackupsectify_...` —— `\b` `\r` 被当转义符吃掉，**不报错** | 脚本里出现 Windows 路径，一律用**原始字符串** `r"..."` 或**正斜杠**。别手动转义 `\`（经过 heredoc / 多层工具会被某一层提前吃掉）。**修法：别重构那段坏路径，按行整行替换**（用没被破坏的片段定位） |
| 401 | `.bat` 里加了中文 `echo`，报错却是 `'Borderlands' 不是内部或外部命令` —— 中文字节被按 GBK 拆成了命令 | 给别的程序读的脚本（`.bat`/`.ps1`/`.tcl`）**一律纯 ASCII**；要中文就传参/传环境变量。**别信"我存成 UTF-8 了"** —— 问题在读它的程序按什么解。配套：脚本里**每个动作都要有自己的成功/失败回报**，`exit code 0` 会掩盖"第一条没跑" |
| 402 | 删文件报"对路径的访问被拒绝"，第一反应是"被进程锁着"（还查了 5 个进程），实际是 ACL | 分不清**锁**还是**权限**时，用一个不触发锁的操作做判据：**改名**。改名成功 ⇒ 没被锁。然后 `(Get-Acl).Access` 看有没有 **`Deny`** —— `Deny` 优先于 `Allow`，且**管理员令牌也包含在被 Deny 的组里**，提权无效，必须先摘 Deny |
| 403 | 从代码读出的"这是两条互斥的路"，代码看起来完全支持，**方向却是反的** | 从代码读出的结构判断，**必须用数据验证一次**。做法：按那个维度把数据分组量（本例 `edge_measured` 29.5 ms vs `lk_measured` 131.0 ms）。更灵的一条：**看那个分支里有没有用到前一个分支的产出** |
| 404 | 调试脚本的"通用递归收集器"报 `TypeError: ... 'list' and 'float'`，报错在求中位那行，**真凶在数据结构** | 分析日志取字段，**优先显式列路径，别写通用递归**（通用收集器分不清"数值"和"列表里的数值"）。先 `print(type(v).__name__, repr(v)[:60])` 看几个样本，比写递归猜结构快得多 |
| 405 | 给方案标"代价"时凭印象写"听起来 DDR 是稀缺资源"，**把最重要的那条路排除了** | 写"代价/风险/会不会成为瓶颈"时，要么**当场算一个数**，要么**显式标注"未算账"**。三步：①找硬件的上限数字 ②按"每帧字节 × fps"列成表 ③算占比 —— **占比 <20% 的别叫它瓶颈** |
| 406 | 分段计时里看到"等待"很长，把它当成了"有余量" | **等待段不是空闲，是上游能力的读数**。`read 45.8（poll 41.0 + rdf 4.8）` 说明上游只给了这么多。**把"等"当成"有优化空间"是方向性错误** |
| 407 | 通篇只算帧率（6.22 / 8.7 / 15.3），据此排优先级，**漏掉了"画面根本不能用"** | 验收图像/视频链路时，**帧率和画面内容是两个独立维度，各测一次**。跑之前先问"这条链路最终要产出什么"（本例产出可校正的图像 ⇒ 第一验收项是亮度/内容）。具体动作：落盘一帧 + 算 `mean`（成本几十毫秒）。**再看分组**：亮度 100% 按分辨率分开 ⇒ 一眼锁定是档位配置，不是光照/噪声 |
| 409 | 往长函数**中间**插了一段代码，它用了**后面 700 行才赋值**的变量 ⇒ `NameError`，整场板上跑废 | 往长函数中间插代码时先问"**我用的这些名字在这一行之前都有值了吗**"，尤其插在某个"初始化段"之前。首选：别引用后面才初始化的东西。❌ 别用"最前面写个 `X = None` 占位" —— 只是把 `NameError` 换成 `TypeError` |
| 410 | 定案改了，只改了**当时手上那个文件**，同目录另外两个还是旧值，而用户跑的恰好是漏掉的那个 | 一个"结论/常量/定案"定了之后，**立刻 `grep` 这个值本身**，看还有几处写着旧值，别按"我改过哪几个文件"来抽。配套：**写寄存器的关键值必须能回读** —— 写错照样出帧，光看帧数永远发现不了 |
| 411 | 一条实测结论只在**某个子场景**成立，我写成了"必须 = X"，还写进了 5 个脚本的注释 | 写"必须/定案/全正常"之前先问"**这是在哪一个子场景量的**"，并把它写进句子本身（✅「`0x4740=0x20` 在 640×480 档实测正常；720p 未验证」）。配套：**一个定案的下游变量有几个？** 只验了其中一个组合就不能外推。不确定就**二分**，别猜 |
| 412 | 在一个**已经写着血账规则**的文件里加新代码，没读文件头注释，新代码正好踩在规则上，两次上板全废 | 往文件里加代码前，**先读文件头 50 行注释**（`sed -n '1,50p'`，30 秒）。注释里写着"板上实测过的时序/顺序约束"的就是**铁律**：新代码与之冲突，要么改设计，要么先做实验推翻它，**不能"先跑跑看"** |
| 413 | 看到某个参数是"软配置"（改一个寄存器就行），就建议把速率提上去 —— 没查**时序是照着哪个速率收敛的** | 建议改任何"频率/速率/位宽/尺寸"之前，**先找约束文件读一遍**（`grep -n "create_clock" *.xdc`，30 秒）。**"这个寄存器可调" ≠ "系统支持这个速率"** |
| 414 | 日志里加了一句"怎么读这段"的说明文字，但**无条件打印** —— 没有异常时也照打，读起来像发现了异常 | 日志里的任何"解释/结论/告警"文字**必须由同一次运行的数据驱动**。规则说明写在**注释**里，不要 `emit` 到日志。✅ `if 有X: emit("⚠️ 有 X") else: emit("✅ 没有 X")` —— 这样日志自带结论 |
| 415 | 只测到"故障与速率相关"，就以为结论定了 —— 实际**两种完全不同的机理都能解释它**（信号完整性 / FIFO 排空） | 得出"A 与 B 相关"之后先问"**还有几种机理能解释这个相关**"，两种以上就别定案。找**独立的第二个维度**：本例"频繁程度"说明与速率有关，"**损坏形态**"（局部花 vs 整行花）才定案。**别把"帮忙看一眼画面"当成低价值工作** —— 本次定案的唯一关键信息是用户说"小花屏" |
| 416 | 同一个 `py` 命令，因为脚本**第一行有没有 shebang**，跑到了两个完全不同的 Python 上（`ModuleNotFoundError: numpy`） | 同一个 `py` 命令结果随**文件**而变 ⇒ 先打印 `sys.executable`（一行）。规避：**分析类脚本一律优先纯标准库**，它可能被任何一个 Python 跑起来 |
| 417 | 加日志字段时锚点字符串唯一、断言通过，**实际改到了错误处理分支**，主路径一个字没动 | **断言"锚点唯一"只证明没改错文件，不证明改对了路径。** 做法：`grep -n "字段="` 把所有相似位置列出来，确认板上实际走哪一条。给"可选路径"的功能加字段时**每条返回都加**。验证方式也要改：不只看"字段在不在"，要看"**值是不是非 null**" |
| 418 | 量到"某步骤让指标变差"，写成"系统在恶化" —— 而那个"差"可能只是**难帧本来就这么难** | 做前后对比前先问"**这两次测量的输入一样吗**"：同一帧前后 ✅ 可比；跨运行 ⚠️ 只要"用户手动做了什么"不受控就不可比。更要紧：**用户的"观感"是一等证据**（用户说"现在挺好的" ⇒ 目标就不是修好它，而是"在好之上省时间"） |
| 419 | 加了 A/B 开关，跑两轮才发现"开关根本没生效"，而**日志里没有任何字段能证明它生效了** | 凡是"可切换的行为"，**开关的实际取值必须逐帧写进日志**（一行就够）。做 A/B 前先证明"**真是两次运行**"：①`RUN_BEGIN` 时间戳是否相同 ②帧 `index` 集合是否子集关系。否则"没生效"和"生效了但没差别"长得一模一样 |
| 420 | A/B 两组一比"整体差不多"，而真正的效果被**两组的场景差异**盖住，最容易硬给一个二选一结论 | 结果"两边接近"时先做三件事：①看关键分桶的**样本量**对不对得上（本例 38 vs 68 帧）②看**受影响帧的占比**两边是否一致 ③看有没有**反向变化**（省了 A 但 B 变多）。写法：**"单帧效果"和"整体效果"分开写**，并显式说明对照质量 |
| 423 | 按"咱的老版本应该也有这个 bug"的假设，把整个实现换成了队友修好的版本 —— **那个 bug 我们根本没有**，反而引入新 bug | **移植任何"修复"之前，先在自己的版本上复现原 bug**；复现不了就不要改。确认两版的对应代码**是不是同一个实现**（同名 ≠ 同一个）。用户说"我们也有这个问题"时，要问"**在哪个版本上看到的、报错原文是什么**"—— 没有报错原文 = 没有复现 = 不该动代码 |
| 424 | 看到某阶段占 5.2 拍/像素就认定是瓶颈，把**最快的那个环节又加快了一遍**，一拍没快（7.160 → 7.162） | 先列出**所有并行的阶段**，各自算每像素占用，**取 max**。只看到"某阶段 stall 计数大"不够 —— 它可能只是在等一个本来就在等别人的环节。改之前先写一句"**改完之后 max(...) 会变成多少**"。stall 计数器要看**改前改后的迁移**，瓶颈搬家了 = 改错地方的直接证据 |
| 425 | 一条**推算**的收益（"读口加宽能让核快 1.38×"）在 5 处文档里活了 **24 天**、跨了三次决策，真动手做了 8 小时才发现是 0 | 文档里凡是没上板/没跑过仿真的收益，**必须写「推算」两个字**。一条推算只要**进了决策**，就要在下一个能验证它的机会上优先验证（成本 10 分钟 vs 拖 24 天）。推算必须写清**前提条件**："1.38×（前提：B 级是唯一瓶颈；若 C 或 coord_gen 更慢则无效）" |
| 426 | `NDIV` 从 8 改成 12（非 2 的幂），仿真**永不结束**：CPU 跑满 20 分钟零进展 | **参数化模块只验证过 {1, 8}，不等于"任意值都对"**。改并行度/深度这类参数**优先取 2 的幂**。区分"卡住"和"慢"：看进程 CPU 时间有没有推进（19.8 min CPU / 20 min 墙钟 = 100% 在算）+ 有没有周期性输出。跑长仿真加看门狗 `timeout` |
| 427 | 给打包成 IP 的核新增了一个 `.v`，仓库里有 9 个，**BD 缓存里只有 8 个** ⇒ `module 'X' not found` | `upgrade_ip`/`generate_target` **只刷新缓存里已存在的副本，不搬新文件**。校验必须**双向**（仓库有、缓存没有，与内容不一致一样是 FAIL）。看到 `module not found` 先 `ls` 缓存目录，**别急着改代码**（报错行号指向调用方，会让人以为例化写错了） |
| 428 | FIFO 有 4 格，TB 跑到最后"最大占用 3/4"，测试全绿 —— 固定周期的激励和 FIFO 的 2↔3 振荡**锁相**，永远碰不到打满那一拍 | 除了"结果对不对"，还要断言**激励真的覆盖到了那条路径**（加 `max_occ` 并断言 ≥3，否则 FAIL）。**伪随机/确定性激励的周期要和被测状态机互质**（用奇数 31/63，别用 2 的幂）。这种"全绿但没测到"的测试**比没写测试更危险** |
| 429 | 在 Python 侧看到"crop 已做偶数对齐"就认定天然满足 —— 但**最终交给硬件的 crop 是 C++ 算的**，那里没取偶 | 看到一个约束在 A 处被满足，**先问"最终产物是从 A 出来的吗"**。跨语言的双份实现，改约束必须两边一起改。**自造向量会继承自己的假设** —— 输入契约要用**真实数据/真实调用链**验。断言要放在**最靠近硬件的那一层** |
| 430 | 算出"51,000 像素 × 95 ns ≈ 4.85 ms ≈ 实测值"，就断定是"numpy 退化成逐元素"，**那个 95 ns 只是凑出来的** | 证明"某机制导致变慢"必须**直接测那个机制**，不能靠"总时间 ÷ 次数"这种事后拟合。**先看分布再下结论**：p10/p50/p90 一拉开（0.98/3.59/15.44）说明主导因素是**抖动**不是吞吐 —— 吞吐问题改算法，抖动问题改调用方式。写进注释的"根因"**必须是已证实的** |
| 431 | 往 notebook 第①单元插开关，**所有行被拼成了一行**，而功能照常工作、所有测试"通过" | 改完 notebook 必须：① `json.load` 回读 ② 每个 code cell 跑 `ast.parse` ③ **肉眼回读插入点前后 10 行**（"全落在一行注释里"语法是合法的，ast 抓不到）。**开关类代码必须验证两个方向都生效**，不能只验证默认值那条路 |
