# scripts/ —— 可直接拿走用的校验脚本（9 个）

> **2026-11-01 重写并合并。** 旧版这里只有一个索引，理由是"怕副本漂移"。
> 但竞赛的评价标准是「**一支陌生队伍拿到该目录，能否直接用在自己的题目上**」——
> 脚本散在别处、路径全是本仓库依赖，别人**拿不走**。
>
> 现在的做法：**脚本正本就在本目录**，全部**不依赖本仓库任何文件**，
> **只用 Python 标准库 / bash**，改两个参数就能用在别的工程上。
>
> 其中 6 个来自并行开发的那一路（2026-11-01 合并），都带 `--selftest`。

## 二、九个脚本

### 1. `check-golden.py` —— 黄金参考比对（507 行）

| 项 | 值 |
|---|---|
| **适用场景** | 改完代码要确认"产物没变坏"。先留一份已知正确的产物当 golden，之后每次都跟它比 |
| **使用方法** | `python3 check-golden.py --ref <参考> --out <新产物> [--pixel-tol N] [--pct-tol P] [--psnr-min DB] [--text-tol F] [--strict-extra]` |
| **判定是三态** | 绿 / 红 / **不确定**（解析不到时不冒充通过）|
| **已验证效果** | `--selftest` 通过：能判绿（一致 / 容差内）、能判红（差字节 / 超容差 / 行数不同 / 缺文件），且**容差写得再大也盖不住"行数不同"和"文件不见了"** |
| **失效条件** | 参考产物本身不是"已知正确"的那一刻起，后面全是白比 |

**⚠️ 最容易用错的参数**：`--pct-tol` 单位是**百分比**（`0.05` = 千分之零点五），
判定只看它；`--pixel-tol` 只负责定义"这个像素算不算不同"。

### 2. `check-timing.py` —— 资源与时序检查（713 行）

| 项 | 值 |
|---|---|
| **适用场景** | 实现跑完，要一句话回答"收敛了没、资源超了没" |
| **使用方法** | `python3 check-timing.py <报告目录或 .rpt> [--wns-min ...] [--lut-max ...]`；`--collect` 可去调 Vivado 采集 |
| **已验证效果** | `--selftest` 通过：负 WNS / 超阈值资源 / 截断的报告 / 非报告文件**全都报红**；正 WNS + 资源充足报绿；**"解析不到"不会冒充通过** |
| **失效条件** | 不是 Vivado 的 `*_routed.rpt` / `*_placed.rpt` 格式 |

### 3. `check-repro.py` —— 可复现性验证（268 行）

| 项 | 值 |
|---|---|
| **适用场景** | 同一份源码跑两次，产物应该逐字节相同。不同就说明有隐藏的随机源/时间戳/路径 |
| **使用方法** | `python3 check-repro.py <目录A> <目录B> [--allow 说明文件]` |
| **已验证效果** | `--selftest` 通过：能判绿（一致 / 允许区间内）、能判红（未声明 / 越界 / 长度不等），**`--allow` 写得再宽也盖不住长度不等** |
| **失效条件** | 产物里本来就有合法的时间戳/绝对路径时不适用（要显式 `--allow` 声明）|

### 4. `gen-host-skeleton.py` —— 从 `.hwh` 生成主机侧调用骨架（718 行）

| 项 | 值 |
|---|---|
| **适用场景** | 手抄 `.hwh` 里的基地址 / 寄存器偏移 / 访问权限 —— **这件事一定会抄错** |
| **使用方法** | `python3 gen-host-skeleton.py <design.hwh> [--out 目录] [--ip 名字]` |
| **它编进去的三条** | ① write-only 寄存器不可读 ② 同一工程可能有 4 字节和 8 字节两种步长 ③ `<FIELD>` 是位号不是字节偏移 |
| **已验证效果** | `--selftest` 11 条全通过：能判红（重复偏移 / 超范围 / 无基址 / 非 XML），**且判红的理由都是预期那一条** |
| **失效条件** | 没有 `.hwh`（例如纯手工 XDC 工程）|

### 5. `dma_xfer.py` —— DMA 搬运与错误判读封装（400 行）

| 项 | 值 |
|---|---|
| **适用场景** | 反复写同一套"arm → 等完成 → 查错 → 复位"的 DMA 驱动代码 |
| **使用方法** | 作为模块 import；`python3 dma_xfer.py --selftest` 看用法 |
| **已验证效果** | `--selftest` 通过：调用顺序、超时、出错判读、复位**都真的走过一遍** |
| **⚠️ 失效条件（原文照录）** | **硬件行为没有验** —— 这份封装未单独上板，第一次用请先拿已知输入跑通 |

### 6. `preflight.py` —— 上板前体检（296 行）

| 项 | 值 |
|---|---|
| **适用场景** | 烧板前扫一遍脚本/批处理，抓那些"在别人机器上才会炸"的东西 |
| **使用方法** | `python3 preflight.py <文件或目录>` |
| **已验证效果** | `--selftest` 通过：bad 的样例全部报红、good 的全部静默 |
| **失效条件** | 只覆盖已知模式，不是通用代码审查 |

### 7. `log_frame_stats.py` —— 从 JSONL 日志算**真实帧率**与丢帧率（本仓库新增）

| 项 | 值 |
|---|---|
| **适用场景** | 每帧记一行 JSON；想知道"实际出了多少帧、丢了多少、慢在哪" |
| **为什么需要** | 帧率 = 帧数 ÷ 墙钟。**`1000/中位数` 会高估 15~20%**；采样日志还要除以采样比 |
| **使用方法** | `python3 log_frame_stats.py run.log --only state=CURRENT --sample 4` |
| **已验证效果** | 本项目 37.6 s 真实日志：识别 3 会话，得上游 16.67/30.73/16.68、本机 16.32/24.34/16.75、丢帧 2.1%/**20.8%**/0%，**与人工逐帧核对一致** |
| **失效条件** | 日志非 JSONL；采样比不是常数（结果偏小，脚本会提示）|

配套样例：[`../examples/sample_frames.jsonl`](../examples/sample_frames.jsonl)。

### 8. `check_synth_log.py` —— 扫 Vivado `runme.log`（本仓库新增）

| 项 | 值 |
|---|---|
| **适用场景** | 仿真全绿、上板却不对；或烧板前花 5 秒确认综合没留隐患 |
| **使用方法** | `python3 check_synth_log.py path/to/runme.log`；`--fail-on critical` 可进提交前钩子 |
| **抓什么** | 多驱动、位宽截断、锁存器推断、端口未连接、常量驱动、跨时钟域 + Critical Warning 与 WNS |
| **已验证效果** | 1850 行真实工程日志：命中 8 处位宽不匹配、48 条 CW，正确判定"综合阶段无 timing summary" |
| **失效条件** | 不是 Vivado 日志。**按关键字匹配、不依赖消息编号**，换版本改名也能用 |

⚠️ 它是**提示器不是判决器**：命中的要人判断。但**多驱动 / 锁存器 / 未连接**这三类建议一律修。

### 9. `verify_package.py` —— 交付包三方一致自检（本仓库新增）

| 项 | 值 |
|---|---|
| **适用场景** | 打包发给别人，对方"装不上"。90% 是**清单、目录、压缩包**三者对不上 |
| **使用方法** | `--dir ./software --manifest release_manifest.json` 或 `--zip pkg.zip --member-root pkg/` |
| **查什么** | ①文件在不在、哈希对不对 ②有没有**清单之外的多余文件** ③目录与 ZIP 文件集是否一致 |
| **已验证效果** | 真实板端交付 ZIP：**369 个文件，缺失 0、哈希不符 0、多余 0** |
| **失效条件** | 清单不是"路径 → sha256"结构（支持两种常见格式）|

## 三、为什么脚本放进来了（变更说明）

旧版理由是「一次复制就有两个正本，会副本漂移」。但那个理由针对的是
**同一个脚本在两个地方各存一份**。

正确解法不是"哪里都不放"，而是**只放一处 + 让另一处引用它**：
本目录是**正本**，工程里的构建/校验流程调用这里的脚本。
这样既没有副本，别人也拿得走。

## 四、两个**没有**收录的脚本（有意排除）

并行开发那一路还带了 `make-copy.py` 与 `sync-check.sh`，
但它们**硬编码了原作者本机的绝对路径**（`C:/Users/<作者>/.claude/skills/...`），
是"维护整合副本 ↔ 外部原版"的本机工具，**外部团队拿不走也用不上**，
与"可复用性"的评价标准相反，故未收进本包。

## 五、怎么用到你自己的题目上

1. **换字段名**：`log_frame_stats.py` 的 `--time` / `--seq` / `--cost` 直接改，不用读源码
2. **换关键字**：`check_synth_log.py` 顶部的 `PATTERNS` 表是数据不是代码，加一行就多抓一类
3. **换清单格式**：`verify_package.py` 的 `normalise()` 只认两种，你的格式不同就改这 8 行
4. **每个脚本先跑一次 `--selftest`**：确认它在你的机器上是对的，再喂真实数据

全部只用标准库（`json` / `re` / `zipfile` / `hashlib` / `argparse` / `xml`），
**Python 3.8+ 直接跑，不需要装任何包** —— 板上、Windows、Linux 都一样。
