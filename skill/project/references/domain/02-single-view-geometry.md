# 领域技能 ②：单视图几何（平面测量 / 长宽比还原）

> **适用范围**：单张图做平面测量、文档校正、尺寸估算、AR 贴平面等。
> **失效条件**：需要相机内参（要标一次焦距，见下）。

---

## 一、⭐ 单张图里"图像中的边长之比" ≠ 真实长宽比

**这是本项目一个被肉眼发现的错误**：同一张 A4 纸，15 个不同角度，
用"图像里四条边的平均长度之比"算出的长宽比是 **0.540 ~ 0.849**（**偏差 -24%~+20%**）。

**表现**：左右倾斜时校正图被压窄，上下倾斜时被压矮。

**为什么**：透视会把某些方向压短。**任何"长度"在图像里都是被投影过的。**

---

## 二、正解：度量校正（metric rectification），有**闭式解**

```
文档平面 → 图像：   H = K [r1 r2 t]
用相机内参归一化：   A = K⁻¹ H  ∝  [W·r1, H·r2, t]
旋转矩阵两列必须:    r1 ⊥ r2 且 |r1| = |r2| = 1
              ⟹   文档真实长宽比  W/H = |A[:,0]| / |A[:,1]|
```

**只需要一个数：相机焦距 f**（主点按画面中心、像素按正方形 —— 现代相机成立）。

```python
def metric_aspect_ratio(quad, img_w, img_h, f_ratio):
    H = cv2.getPerspectiveTransform(unit_square, quad)   # 单位正方形 → 图像四边形
    f = f_ratio * img_h                                   # 焦距（像素）
    cx, cy = img_w / 2, img_h / 2
    a11, a12 = H[0,0] - cx*H[2,0], H[0,1] - cx*H[2,1]     # K⁻¹H 的前两列
    a21, a22 = H[1,0] - cy*H[2,0], H[1,1] - cy*H[2,1]
    n0 = sqrt((a11**2 + a21**2)/f**2 + H[2,0]**2)
    n1 = sqrt((a12**2 + a22**2)/f**2 + H[2,1]**2)
    return n0 / n1
```

**实测效果**：15 个角度的长宽比波动从 **45% → 2.3%**，
均值 0.7088 vs A4 真值 0.7071（**误差 +0.24%**）。

> ⭐ **性能**：< 0.1 ms/帧，**可以放进视频循环**，比"网格自标定"（两趟、且只对方格纸有效）好得多。

---

## 三、⚠️ 不要"采数据拟合" —— 先问"这有闭式解吗"

**本项目的真实对话**：使用者观察到"倾斜越大压得越窄"，
提出"采集不同角度的数据，拟合一个'倾角→拉伸程度'的函数"。

**这个思路不成立**，两个原因：

1. **它不是单个角度的函数** —— 还取决于**相机焦距**和拍摄距离。
   同一个倾角，广角和长焦的结果完全不同。拟合会缺一个维度。
2. **它有闭式解**（上一节）。拟合只会引入本来不存在的误差，而且外推极不可靠。

> ⭐ **判据**：问题描述里出现 **"旋转矩阵""正交约束""内参""投影"** 这类词，
> 通常都有闭式解。**先查公式，再考虑拟合。**

---

## 四、焦距怎么标：不用买标定板

**拿同一张纸拍 5~9 张不同角度**，让"各张算出的长宽比**最一致**"来反解焦距。

```python
best = None
for fr in np.arange(0.15, 3.0, 0.0005):
    v = [metric_aspect_ratio(q, w, h, fr) for q, w, h in quads]
    s = np.std(v) / np.mean(v)
    if best is None or s < best[1]:
        best = (fr, s, v)
```

**判据是"各张的离散度"**：< 1% 就算标得好。

### ⚠️ 必须搜【比例】不是【像素】

**焦距（像素）随图片分辨率线性缩放。** 本项目样图有两种高度（1200 / 1280），
一开始按"统一像素焦距"搜索，把两种尺度混在一起 —— **标定值偏了 3%**。

存 **`f / 画面高度`** 这个比例，则**跨分辨率通用**
（实测两种分辨率混用仍然吻合）。

实测 15 张标定出 `f/画面高 = 0.7330`（等效 903 px @1232 高，**视场角 68°** ——
正是手机主摄的典型值，说明标定结果物理上合理）。

## 五、参数与内参的一致性（跨端交付必查）

| 项 | 说明 |
|---|---|
| `f_ratio` 与分辨率 | 存比例则无关；若存像素值，**缩放图片时必须同步缩放 f** |
| 内参变化 | **换相机 / 改变焦（拉近拉远）必须重标** |
| 不标定也能跑 | 设 `CAL_F_RATIO = None` 时自动退回"图像边长相除"，精度差但可用 |

## 六、其它单视图几何的坑

| 坑 | 说明 |
|---|---|
| **`warpPerspective` 默认把矩阵当正向变换** | 我们的 `H` 是"输出→输入"的采样映射，**必须加 `cv2.WARP_INVERSE_MAP`**，否则 OpenCV 会再求一次逆 → 结果完全错乱（但 H 本身没错，很难一眼看出） |
| **四角点顺序不是随便排的** | 流式架构要求"上边缘映射到输出第 0 行"，顺序反了行缓存就退化成整帧缓冲 |
| **直线度残差反映的是镜头畸变** | 项目实测校正后直线仍有 ~3 px 弯曲 —— 那是**手机镜头的桶形/枕形畸变**，不是算法误差。**不标定畸变系数就消不掉** |
| **角点检测容易抓到纸边缘之外** | 多阈值 + 边界拒绝 + 取最大轮廓（最外围） |
