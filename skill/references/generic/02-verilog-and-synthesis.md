# 通用技能 ②：Verilog 语言与综合

> **适用范围**：任何手写 Verilog RTL 的项目。
> **失效条件**：用 HLS / 高级综合的项目，部分条目不适用。

---

## 一、位宽：Verilog 会**静默**截断，而且规则反直觉

### 坑：多驱动（multi-driven net）

改了信号的驱动方式（比如从"寄存输出"改成"组合 `assign`"），
**忘了删掉 reset 块里的旧赋值** → 两个 always 块驱动同一个信号。

```verilog
// ❌ 组合块里 assign，reset 块里还在赋 0
always @(*)   rd_en = (state == S_RD0);
always @(posedge clk) if (!rst_n) rd_en <= 1'b0;   // ← 多驱动！
```

**症状**：**仿真侥幸跑对**（Verilog 的 last-write-wins 语义），
**综合报 69 条 CRITICAL WARNING**，硬件行为未定义。

> ⭐ **改驱动方式时，一定要全局搜一遍这个信号名，把旧的赋值删干净。**
> 这是本项目踩得最狠的一条（69 个 CW）。

### 坑：乘法会静默截断

```verilog
wire [11:0] coord;   wire [31:0] param;
wire [31:0] r = param * coord;      // ❌ 结果可能被截断
```

**规则**：乘法结果的宽度 = **两个操作数里最宽的那个**（不是相加）。
`32 位 × 12 位` 在 Verilog 里按 32 位算，高位丢掉。

```verilog
// ✅ 先显式加宽到足够位宽再乘
wire signed [55:0] a_e = {{24{a[31]}}, a};
wire signed [55:0] p   = a_e * sv_e;        // 56 位 × 56 位 → 112 位，取低位够用
```

**症状**：大参数下结果错得离谱，小参数下"看起来是对的"——
**所以只在参数取极值时才暴露**。

### 坑：累加器要留够余量

本项目的坐标累加器 `ACC_W = 56`，就是为了让
`a12*sv + a13*65536` 这类三项相加不溢出。**算一遍最大值再定位宽，不要猜。**

## 二、时序：组合逻辑别在一拍里塞太多级

```verilog
// ❌ 4 次乘法 → 加法 → 2 次乘法 → 42 位加法 → 舍入，全在一拍
wire out = ((ify*(ifx*p00+fx*p10) + fy*(ifx*p01+fx*p11) + (1<<31)) >> 32);
```

**实测 WNS = -6.878 ns**（10 ns 周期下最差路径 16.9 ns）——
**仿真完全看不出来**，综合报告才暴露。

```verilog
// ✅ 拆两级流水
// 第 1 级：横向插值
always @(posedge clk) begin a_r <= ifx*p00 + fx*p10; b_r <= ifx*p01 + fx*p11; end
// 第 2 级：纵向插值 + 舍入
always @(posedge clk) pixel <= (ify_r*a_r + fy_r*b_r + (1<<31)) >> 32;
```

> ⚠️ **改了流水级数，上层等待的状态数必须同步改** ——
> 否则数据会晚一拍到，表现为整体滞后一个像素。
> **在模块头注释里写清"延迟 = N 拍"。**

## 三、仿真与综合不一致的几类典型

| 现象 | 真因 |
|---|---|
| 仿真对、上板错位一格 | 控制脉冲做成了**寄存输出**（见 `01-stream-handshake.md`） |
| 仿真对、综合报 CW | **多驱动**（本文件第一节） |
| 仿真对、上板结果错 | **位宽静默截断**（本文件第一节） |
| 仿真里读出 X | 读了**没写过的存储单元**；上板会读到"残留值"而不是 X，所以**表现不同但同源** |

> ⭐ **最后一条特别值得记**：仿真的 `X` 和上板的"随机残留值"是**同一个 bug 的两种表现**。
> 见到仿真报 X，不要以为"只是仿真没初始化" —— 它在硬件上一样是错的。

## 四、TB（测试平台）写法要点

详见 `05-verification-method.md`，这里只列语言层面的坑：

| 坑 | 现象 | 对策 |
|---|---|---|
| `integer` 默认是 **X** 不是 0 | `if (n < 10)` 静默不成立，调试打印不输出 | 所有 integer 显式初始化 |
| 信号**声明必须先于使用** | `Could not find variable` | 被 always 引用的信号，声明提到文件靠前处 |
| `$clog2` 需要 `-g2005` | 默认档编译失败 | `iverilog -g2005` |
| 混用 SystemVerilog 语法 | `-g2005` 下报一堆语法错，**且错误位置指向无关文件** | 本仓库统一 Verilog-2005：轮询用 `while` 代替 `fork/join_any`，X 检测用 `(^x === 1'bx)` |
| `$readmemh` 读到整个数组 | `Not enough words`（无害但吵） | 用带范围的形式 `$readmemh(f, mem, 0, N-1)` |
| `$dumpvars(0, tb)` | **写出 GB 级 VCD**（本项目单个 3 GB） | 波形改成**默认关闭**（`` `ifdef DUMP_VCD`` + 显式开） |

## 五、⭐⭐ 并行除法器的除数**只能是 2 的幂**

> 2026-10-17 之前：想用 `NDIV=12` 换一点吞吐，结果**仿真永不结束**，CPU 100% 但没有任何输出。

| 除数 | 结果 |
|---|---|
| 8 / 16（2 的幂）| 正常，组合逻辑等价于移位 + 少量比较 |
| **12（非 2 的幂）** | **仿真挂死**；综合出来的除法网络规模爆炸 |

**根因**：参数化的"多路并行除法"通常靠**乘倒数 + 移位**实现，
倒数只有在除数是 2 的幂时才能用移位精确表示；非 2 的幂会退化成真正的除法器阵列。

**⭐ 判据**：改这类参数前先自问"是不是 2 的幂"；
**仿真跑超过预期时间且 CPU 满载、无输出** ⇒ 先怀疑除数，而不是"波形太大"。
