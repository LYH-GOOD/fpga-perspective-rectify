# 08 · 机械闸与自检的自我失效

> **适用范围**：**任何有"配置文件 / 生成物 / 检查脚本"的工程** —— 换题换板仍然可用。
> **什么时候读**：① 要加一个检查脚本之前 ② 检查脚本"通过了"但你不放心 ③ 同一个参数在多处出现。
> **来源**：本项目 2026-09-25 ~ 10-02 的真实事故（配置三份拷贝、自检脚本自己卡死、进程模型掩盖 bug）。

---

## 一、⭐ 核心原则：**靠机制，不靠纪律**

> **"下次记得"必然烂。** 而且烂得很隐蔽 —— **不一致会制造"我在遵守"的假象，比完全不做更难发现。**

**⇒ 凡是一条"要记得做"的规矩，都该配一个**机械闸**：
**一段代码 / 一个脚本 / 一个断言**，它**自己会报错**，不依赖人的记忆。

| 靠纪律（❌） | 靠机制（✅） |
|---|---|
| "记得每次改完同步文档" | `check_docs_sync.py` 扫 git 历史报出来 |
| "记得把配置改对" | 从**唯一正本**读出来 + **回读比对** |
| "记得跑仿真" | 生成脚本里直接串上，跑不出结果就报错 |

---

## 二、⭐ 同一个事实有【多份拷贝】⇒ 必然不一致

**真实事故**（`2026-09-30_board_cfg_color`）：
一个板卡配置（`NCH/PIX_W/DW/ROWS/MAX_W`）**散在三处**：

| 拷贝 | 位置 | 谁在用 |
|---|---|---|
| **正本** | `build/create_bd.tcl` 里一行 `dict create ...` | BD 回读校验 |
| 副本 2 | `find_homography.py` 的 `PL_LINE_ROWS` | PS 侧安全闸 |
| 副本 3 | iverilog 的 `-D` 参数 | 仿真 |

**不一致的后果**：
- **要么放行核装不下的配置** ⇒ **画面冻结**
- **要么白拒一个能跑的配置** ⇒ 白折腾

### ⇒ 修法：**只留一个正本 + 每份拷贝配一道闸**

```
                                ┌─ 闸1：-D 传给 iverilog 后【回读 TB 里的宏】比对
正本（一处） ──读出来──► 分发 ──┼─ 闸2：PS 常量 == 正本
                                └─ 闸3：<其它使用方> == 正本
```

**⚠️ 两个必踩的细节**：

| 陷阱 | 说明 |
|---|---|
| **`-D` 名字写错 ⇒ 静默用默认值** | 编译不报错，**检查跑在另一个配置上** ⇒ **必须回读比对**，不能只看"没报错" |
| **加了新拷贝却忘了加闸** | **每新增一处使用，就要新增一道闸** —— 这是"改了规则、有东西悄悄掉出去" |

### 2.1 2026-10-31 补：**"清单里的哈希"也是一份拷贝，而且它不会自己更新**

交换一份源文件（本例把 RTL 换成快的版本）之后，仓库里立刻出现**两份互相矛盾的事实**：

| 拷贝 | 内容 | 谁在用 |
|---|---|---|
| 源文件本身 | 新的字节 | 综合、编译 |
| `source_sha256.json` / `release_manifest.json` / `checksums.json` | **旧的哈希** | 完整性校验、安装本 |

**症状分两种，都很贵**：

- 校验方**严格** ⇒ 直接拒绝启动（"文件版本或内容不一致"）
- 校验方**宽松** ⇒ **静默通过**，于是你以为校验覆盖了它，其实没有

**⇒ 修法**：**任何"替换源文件"的动作，都必须伴随一次清单重算**，
并且清单工具要能**全量复算 + 报告哪些项变了**（本例：398 项里只有 2 项变化，
一眼就能确认"只改了该改的"）。

**⭐ 判据：改完文件后，跑一次 `--check`；输出必须是"0 项不符"，不能是"我没改别的"。**

### 2.2 2026-10-31 补：**残留的构建产物会伪装成"脚本坏了"**

| 现象 | 重建脚本第一句 `error: build exists; choose a fresh extraction` |
|---|---|
| 真相 | 上一次失败的构建在本机留了 `build/`，脚本**故意**拒绝在脏目录重建 |
| 危险 | 若不假思索地删掉这句检查，就会在**半脏的目录里增量构建**，得到不可复现的 bit |

**⇒ 修法：打包时显式排除构建产物**（`build/`、`.Xil/`、`__pycache__/`、`.vivado-ai/`），
让"打包"和"干净解压"成为同一件事。

## 三、⭐ 自检脚本自己会坏 —— 症状却像"被测对象坏了"

**真实事故**（`2026-09-30_pl_selftest_rewrite`）：

```
overlay 已加载: system.bit
VERSION = 0x00010004          ← ✅ 板上是【新的】比特流
配置完成 STATUS=0x00000008    ← ✅ 寄存器通路好的
Traceback ...
  dma.recvchannel.wait()      ← ✗ 永久阻塞
```

**看起来像"PL 核坏了"，其实问题在那个自检脚本里。**

**⇒ 排障惯序（先确认"什么是对的"，再缩小范围）**：

1. **先看那些【已经对了】的证据** —— 比特流版本对不对？寄存器读写通不通？
2. **它们都对 ⇒ 问题不在 PL** ⇒ 往上一层的自检脚本/驱动查
3. **⚠️ 别一上来就怀疑最复杂的那部分**（核/算法）—— 简单的东西也会坏

> 💡 **通用化**：**"检查工具坏了"和"被测对象坏了"表现完全一样。**
> ⇒ **先证明检查工具本身是好的**（本项目的做法：先跑一个"硬编码参数的已知良好通路"自检，
> 把它和"自适应主流程"分开，前者过了才说明通路没问题）。

## 四、⚠️ 进程模型会【掩盖 bug】

**真实事故**（`2026-09-30_video_onboard_D2`）：

> 旧路径用"**每张图一个子进程**"，把三件事**掩盖了很久**：
> ① overlay 是否只加载一次 ② 多帧之间会不会串帧 ③ 长驻进程下状态有没有残留

**换成"长驻进程连跑多帧"之后，多帧 bug 立刻现形。**

**⇒ 判据**：

| 进程模型 | 掩盖什么 |
|---|---|
| **每样本一个进程** | **状态残留 / 串帧 / 只加载一次 / 全局变量** |
| **长驻进程** | 暴露上面全部，但**短测可能看不出来**（要跑够多帧）|

**⇒ 交付/验收要按【最终运行方式】来测**，而不是怎么方便怎么测。

## 五、⭐ 交叉对照：**两套独立实现**能定案

**真实事故**（`2026-10-01_teammate_detector_crosscheck`）：

> 同一段 190 帧素材：**我们的检测器跳 12 次，他们的 0 次**；
> 但**在正常帧上两者逐角中位差仅 0.40 px** ⇒ **分歧只发生在我们跳的那几帧**
> ⇒ **他们的检测器在我们的【错误帧】上给出了正确的解。**

**⇒ 这是最强的定案手段**：**两套独立实现**在同一批数据上跑

| 观察 | 结论 |
|---|---|
| 两套**在正常样本上高度一致** | ✅ 两套都没写错（**互相印证**）|
| 两套**只在失败样本上分歧** | ⭐ **直接指出哪几帧有问题**，且**其中一套是对的** |
| 两套**处处都不同** | 说明**规格本身没定义清楚**，先去对齐规格 |

> 💡 **本项目的通用做法（可照搬）**：**"PS 金模型" 与 "RTL 仿真期望值" 是两套独立实现**，
> 每次改动都交叉检查 —— **只验一套 ⇒ 上板判据不可信**。

## 六、⚠️ 副本漂移：**复制一份 = 从此有两个正本**

**真实事故**：本仓库**已经因为"副本漂移"栽过两次**（`pitfalls.md` #93~#97）。

```
一次复制 ⇒ 两个正本 ⇒ 改了一个忘了另一个 ⇒
两边都"看起来对"，但行为已经不一样 ⇒ 最难查的一类 bug
```

**⇒ 对策（本项目采用）**：

| 场景 | 做法 |
|---|---|
| 交付包要带脚本 | **由脚本按显式清单拷贝**（`make_package.py`），并在打 zip 后**核对计划内文件是否齐全** |
| 技能包要引用脚本 | **只写索引，不复制**（`skill/scripts/README.md`）—— 正本永远在 `build/` `sim/` |
| 引入上游第三方内容 | **上游原件一字不改** + 另写一个"适配层"文件 ⇒ 可升级、可对账 |

**⚠️ 显式清单必须【完整】**，而且要配一道 **"计划外的文件报出来"** 的检查
（本项目踩过：改打 zip 规则时，`.gitignore` 被静默丢掉了）。

---

## 七、一页速查

```
要加一条"记得做"的规矩 → 能不能做成脚本/断言？（能就别靠纪律）
一个参数出现在 ≥2 处   → 定一个正本，其余每处配一道回读闸
检查"通过了"           → 先证明检查工具本身是好的
排障看到"全错"         → 先找"哪些是对的"，用它们缩小范围
换进程模型             → 会暴露/掩盖不同类的 bug，按最终运行方式测
怀疑某个环节           → 用两套独立实现交叉对照
想复制一份文件         → 停一下：这是第二个正本了
```
