# 嵌入式触摸界面与实时输出

## 适用场景
带实时相机、仪表或数据流的设备界面，尤其是PYNQ的Python与缓存图像合成。换题或换板时先重测分辨率、物理尺寸和触摸映射；不依赖特定矫正算法。

## 使用方法
1. 先确认实际运行版本、渲染器、画布、原图尺寸和显示矩形。不能从旧截图推断当前坐标，也不能把网页设计库直接替换为React或Qt。
2. 给控件建立唯一几何声明，绘制位置、触摸命中、按下反馈共同引用它。目标尺寸以物理屏幕和实际触摸测试决定；本项目采用至少48像素作为起点，不把像素阈值视为所有设备的通用保证。
3. 字体需覆盖中文字形。数字与FPS标签使用同字族、同字号、同基线。先离线生成图集，再缓存到设备；不要逐帧加载字体、解码背景或运行全图滤镜。
4. 保持单一显示提交者。触摸回调只更新状态，不能独立改写正在扫描的DMA缓冲区。滑条立即反馈，硬件参数在帧边界统一生效；高频拖动只保留最新值，松手后保存。
5. 进度对应真实阶段，结束条件对应实际有效输出提交。没有可测量总量时使用阶段条，不捏造百分比；失效或取消时要结束旧进度。
6. 从显示点还原源点必须扣除预览原点并应用缩放。例：800×600源图显示在(0,124,640,480)时，触摸(400,364)对应源图(500,300)，不能直接传(400,364)。裁剪或旋转存在时还须逆变换。
7. FPS只统计真正成功提交的新有效输出。统计窗口和刷新间隔分开配置，扩大窗口只是平稳数字。布局切换可重置统计代次；启动窗口未充满时会从低值建立，不能误读为稳定性能下降。

## 可直接运行
在提交包根目录运行：
```sh
python3 skill/scripts/check-ui-layout.py skill/examples/ui-layout.json
python3 skill/scripts/check-ui-layout.py --selftest
python3 skill/ui-ux-pro-max/scripts/search.py "touch target feedback" --domain ux
```
离线检查器检查声明的矩形、字号、窗口和坐标函数；不检查截图中文字是否挤压，不访问硬件，也不保证板端FPS。绘制后仍需按实际分辨率看图，上板检查触摸、闪屏和真实吞吐。

## 来源与已验证效果
来自本项目600P点选偏移、控件视觉位置与命中不一致、进度结束条件错误及FPS短窗跳动的观察。当前规则与第33版源码及既有44项主机检查中的对应交互用例核对；本包另提供可独立复现的声明检查，结果见examples/validation。没有通过跨板A/B证明整套UI方法能够提高FPS，不能作此承诺。

## 失效条件
裁剪、旋转、畸变映射不满足纯缩放假设时需扩展坐标函数；网页、Qt、LVGL的帧所有权与渲染方式不同。真实像素效果、LCD物理刷新率、触摸精度仍需设备验收。
