# 第16版：短时实时延续与显式AI入口锁

基于第15版，不训练，不修改跟踪算法或FPGA。303项主机检查和八图真实Windows NCNN通过，板端实时帧率仍需实际验收。

## 切换规则

- 普通实时矫正：第15版自动/AI恢复策略保持。自动调用AI不会启用入口锁。
- 手动点击AI：AI找不到时保持AI，按首次3秒、后续5秒冷却重试；首次显式请求仍独立于自动请求预算，后续重试沿用3次/分钟预算。
- AI实际找到并输出有效矫正后：短暂失效最多延续1秒；达到原有2秒无有效输出条件，或确认目标离场，解除锁并恢复先自动、再AI。空场仍等待目标返回，新目标进入后先自动。
- 重新找四角、并排/仅矫正切换继承当前锁；显式选自动、手动、退出解除锁，再次点AI重新启用。

## 减少闪屏

延续的是四角/变换，左右仍使用同一个当前相机帧，不缓存冻结上一张右图。只接纳前端明确标记的HELD结果，最长1秒从最后一次既有有效几何结果计算；HELD不能续期。超过上限、目标确认离开或代次切换后清除旧矫正，原图保持实时。

确认换书/目标离场后沿用原有代次作废；现有跟踪明确报告运动过大、出画或四角越界形变时立即取消延续，后续弱帧不能复活旧位置，必须重新取得有效四角。普通单帧FB不一致仍允许短时延续。只复用既有失败原因，没有新增颜色、纹理、运动检测门槛。

沿用已有旧UI/旧代次拒绝及500毫秒帧新鲜度，生产者停顿时原150～250毫秒实时原图保护保留。1秒不是旧像素驻留时间。

有效CURRENT与延续输出的框均保持绿色；底栏LIVE CONTINUITY表示短时延续，AI LOCK只表示显式入口锁。CORR(valid)仍只统计有效CURRENT；延续输出只计实际显示，不能刷新丢失计时。

## 帧率与验收

相机640×480/30、HDMI1280×720/最高30、模型、现有光流、点数、PL执行、CMA槽数均保留。复用原有HELD当前帧矫正执行结果，新增常规工作为少量标量元数据判断；未增加AI或光流调用。

主机9轮交替测量见continuity16_benchmark.json。主机模拟HDMI/转换耗时不能证明PYNQ板FPS；实际对比相同场景的CORR(valid)与DISP，并测试短暂遮挡、运动、连续换书、手动AI失败与普通自动调用AI。1秒延续期间运动过大时可能短暂偏位，本轮没有改跟踪预测算法。

旧pic56/paired/overlay报告仅供版本追溯，本报告和continuity16_validation.json为本次改动依据。
