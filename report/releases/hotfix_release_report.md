# 第10版：计时修复、切换进度条、新目标先自动

基于已交付第9版独立迭代，旧版ZIP和安装本保留。本版不重新训练，不更改模型、物理边缘/手动跟踪内核、FPGA文件或相机/DMA所有权。

## 修复内容

1. **换书计时报错**：候选轮廓消失时，轮廓框、计数、开始时间和稳定时间一起重置；新目标锁定清理上一目标的候选历史。即使残留轮廓框却没有开始时间，也按首次观察重新计时。辅助场景检查中的数值异常只重置本次检查并记录完整错误栈，相机和硬件生命周期错误继续按原有方式安全退出。
2. **切AI时黑屏**：旧版在没有矫正结果时清空结果区域，原图仍在左侧；显示线程还可能提交没有原图也没有结果的启动画布。本版在搜索/AI/恢复时显示居中的实时原图，使用原有1280×720画布、原生1:1转换和不可写普通内存快照。相机帧尚未到达时显示原来的中央进度条，收到原图后显示原来的顶部进度条。不把旧矫正图无限保留，不把原图计为有效矫正。进度条随实际阶段更新，没有新增动画、字体加载或虚构百分比。
3. **新目标先自动**：确认空场景后，新的目标稳定出现，先使用现有相机流自动重新找角；自动超时才尝试AI。底部“空场景·先自动”与日志一致。显式点击AI仍直接进入AI，真正手动保持用户控制。

## 现在的切换逻辑

普通进入或新目标稳定出现 → 自动找角 → 自动超时才AI → AI给初始四角 → 原手动策略跟踪。

短暂丢失先恢复同一目标；连续约2秒无有效矫正才重新自动找角。恢复自动搜索通常3秒，正在处理/已有候选给予有限宽限，总上限4.5秒；失败再AI。AI未找到或当前帧核验失败，也能回自动恢复。两轮快速恢复后按5/10/20秒冷却，自动AI请求仍最多每滚动分钟3次。明确空场景不会被当成低帧率的有效矫正。

普通冷启动保留曝光稳定及搜索宽限，总上限8秒；本版没有增加每帧AI推理。AI定位成功后继续复用原手动跟踪及同目标恢复。

## 验证与性能范围

检查覆盖：初始化过候选后短暂消失再在原位置出现、缺失开始时间、新目标重置、白底和木纹各50次图像换书、短遮挡和播放视频、返回目标自动成功不消耗AI预算、自动失败再AI、AI拒绝恢复、相机错误、取消和旧代结果隔离、真正手动不被接管。

实际HDMI合成函数在假设备上执行，检查并排/只看结果两种布局、原图持续显示、无帧原进度条、阶段推进、正常结果恢复时旧区域清除、旧代画面拒绝，以及原反馈层不会重复遮挡原图。1280×720预览已检查。

正常跟踪没有增加图像检测、AI调用、图像拷贝、缩放或新的原生转换。计时修复位于原有最高2Hz的辅助检查，新增完整错误栈只在异常事件时生成。正常控制开销和第9版作主机成对比较，具体结果见hotfix_steady_benchmark.json。主机测试不能替代PYNQ相机/HDMI的实际帧率验收。

## 安装与板端测试

把本版ZIP与install_ai_hotfix_full_20261027_10.ipynb上传到Jupyter同一目录。停止旧程序，运行安装本全部单元；安装到新目录并保留旧目录。四图AI自检与CPU检查成功后，进入打印的新目录，重启内核，再运行p11_start.ipynb。

优先测试：同一位置连续换书至少20次；短暂拿手遮挡；目标拿走后再放回；白布上的平板播放视频；自动→AI和AI拒绝→自动时的原图/进度条；真正手动是否仍可稳定工作。

比较第9/10版时请用同一相机参数、目标、背景、显示布局和光线，分别看有效矫正CORR(valid)、显示DISP和切换耗时。原图等待期间CORR(valid)=0属于真实“暂无有效矫正”，不会用显示帧率冒充矫正帧率。板端FPS和真实HDMI黑屏情况仍由你上板确认；交付包不声称已经测得板端帧率不变。
