# 手动保持与跨背景跟踪修复版 trackfix-20261026-5

本版基于 physical-4，修复手动跟踪失败后被自动前端接管，以及物理边缘只接受“背景比黑边亮”的限制。当前模型权重沿用 physical-4，目标仍是平板外壳物理四角、包含黑色边框。

## 使用行为

- 手动框选后持续保留手动目标。原有双向光流正常时沿用原快速路径；失败后重试同一特征锚点，必要时改用同一边界的局部恢复，不启动全画面自动检测。
- 短暂失败最多保持上次可信矫正 1.5 秒，超时显示丢失和原始预览。继续尝试同一目标；重新发现后经过两帧边缘和形状核验再恢复。旧坐标不会无限续期。
- 原来无特征而固定的手动目标，若能证明四条物理边界，可改用边缘跟随；四边也无法辨认时仍明确使用 FIXED。完全遮挡、出画面或外框与背景无可见差异时，不能保证持续追踪。
- 物理边缘接受两种明暗方向，并结合边框内侧亮度参考、邻近位置、四边直线分布和形状约束。不会仅因屏内出现更强梯度就直接接受为外框。
- 正常物理跟踪保持原来的小窗口。丢失后按 8/16/32/40 个观察像素逐级扩大，宽搜索最多约 5 次/秒，候选确认可紧接下一帧；640 宽输入对应最大约 ±80 像素。运动超出范围时可用“重新找四角”重新选定。
- AI 初始化未通过物理边缘证明时，会记录 AI_TRACKER_FALLBACK 及原因；旧 FB 分支也沿用手动目标保持策略，不再静默交由自动检测接管。

## 性能措施与证据

把逐条边缘采样和稳健拟合合并到不依赖 OpenCV 头文件的小型 C++ CPU 模块。板端首次安装编译一次，之后按源码摘要复用。正常手动光流不额外运行边缘检测；大窗口仅用于丢失恢复。正常自动、相机、HDMI、像素后端、已有原生内核、bit/hwh、模型图与权重均逐文件核对不变。

23 项跟踪/控制回归通过，涵盖暗背景、亮背景、明暗切换、混合背景、纹理背景、播放视频、平移/旋转、遮挡重现、48 像素突变、内屏误捕拒绝、恢复频率限制、手动不转自动、保持超时与恢复。另 21 项原 AI 流程回归通过。26 张 PIC4 均能建立当前边缘证据，这是已有照片回放，不是独立跨背景准确率。

同一组 99 帧主机输入，旧版与本版均 99/99 当前输出，跟踪中位数从约 1.66 ms 降至 1.07 ms，P95 从约 2.26 ms 降至 1.61 ms；最大角点误差均约 1.44 像素。数字以随包 trackfix_validation.json 中的原始报告为准。已实际编译并执行 Windows 原生内核；另通过 Cortex-A9 ARMv7 目标编译检查。尚未在 ARM 上执行或测量实际 HDMI/相机帧率，不能把主机结果当作板端帧率保证。

在 PIC4 4007 的可见原图里，原有临时标签的上边约向内偏了 8 像素。新实现对歧义种子仅在初始化时尝试内侧外观约束与一次 4% 外扩假设，仍要求四边通过。原训练标签、训练数据和权重本轮均未修改；照片回放不能用这些临时标签声称亚像素精度。

## 安装与板端测试

1. 将完整 ZIP 和 install_ai_trackfix_full_20261026_5.ipynb 上传到 Jupyter 同一目录。停止旧程序，执行安装 notebook 全部单元；安装保留旧目录。
2. 安装会进行原有四图 NCNN 自检和新增 CPU 内核自检。CPU 检查不打开相机、HDMI 或 PL；结果保存为 trackfix_cpu_check.json。若原生模块不可用，自检会明确失败，便于发现编译问题。
3. 进入新目录，重启内核，运行 p11_start.ipynb，确认日志 RUN_BEGIN 为 p11-rgb-pspl-v9-ai-trackfix-20261026-5。
4. 手动框选后先固定，再轻移，短暂遮挡后放回；检查是否始终保留手动模式，恢复后是否仍是同一物体。分别测试明亮桌面、暗背景和有纹理背景。
5. AI 矫正同样测试播放视频的平板，先静止再缓慢移动，记录角点抖动与丢失恢复。对比时使用同一场景、距离、曝光、输出尺寸和动作。
6. 提供新 run-result.log 与 trackfix_cpu_check.json，评估正常稳定段的有效矫正率、显示率、tracker_s 中位/P95、LOST 比例。只看屏幕刷新数字不能判断有效矫正帧率。

曲面展平不在本次修改范围内。原版本 ZIP、安装文件与训练数据保留。
