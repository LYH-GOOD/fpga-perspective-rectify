# 第21版：V18基线，相机全路径复用与2秒恢复冷却

本版从用户提供的314文件V18包迭代，保留480P/600P档位、输入容量预分配、检测/跟踪/物理外边缘、模型权重、图像与显示优化、FPGA bit/hwh。

## 已实现规则

- 自动转AI已开启。丢失确认1.2秒，实际SEARCHING后无候选1.5秒；不晚于1.5秒已出现且仍有效验证的候选，可继续到同轮搜索开始后的2.8秒。失败或重复搜索不续期，READY结果优先。搜索前曝光稳定及8秒保护分开处理。
- 每次恢复冷却统一2秒，第一回和后续相同。主页/静态页的相机停放期限是独立的3秒，AI稳定证明也是独立的3秒。
- 短暂失效最多1秒用可信四角矫正当前像素；延续帧不刷新可靠时钟，不冻结旧画面。确认离场/换目标/硬运动沿用原清除规则。
- AI成功实际输出且连续稳定3秒、有效输出率>=4后，只退还本次请求预算；失败/未稳定限制3次/分钟保留。手动AI未找到时保持AI，已输出后丢失按原路由回AUTO；真正手动权限保持。

## 相机交接

AUTO/AI/手动/refind/点选目标/拍照的入口出口统一使用同一个相机管理器。健康同档位保持采集线程和视频流，旧消费者/lease归还后交接，不继承旧书的四角和跟踪器。普通布局切换继续复用。

手动入口取一份新鲜独立选角图，不再因同档位进入而重开USB。选角确认后的手动算法保持V18。直接切换时预览绑定新代次，采集继续更新；主页和静态页停放时关闭预览复制，手动选角后解除采集预览，避免给正常手动仅矫正显示新增复制。

短暂返回主页、拍照完成后的3秒内支持接管；超时、应用退出或相机异常释放资源。已有静态照片改四角继续用独立原图，不额外打开相机。

480P/600P实际参数改变时，增加CPU相机辅助库reconfigure接口，尽量保留设备fd，但必须停流、释放旧MMAP、重建缓冲、重新稳定。新旧视频流使用不同的uint64帧凭据代次；旧凭据不能归还新缓冲。驱动拒绝时关闭后完整打开，失败档位回退；设备准备成功后才提交显示/后端/UI参数。480P仍320跟踪尺寸，600P仍400，最大输入容量保留。

只有已记录完成稳定或已有可靠选择/接管的流才跳过重复稳定；冷启动早期切换不能把“采集线程活着”当成稳定完成。

## AI与切换工作

重复AI/转手动选角时可有界丢弃旧推理结果，完整消费旧协议、跳过旧拟合/应用，尽量复用单个模型进程。上限2秒且不越过原请求期限。新AI实际发送前等服务可用，再取最新帧，不提前消耗请求名额。进入AUTO或正常跟踪仍需旧计算退出；选角等待/AI等待阶段与正常跟踪区别处理。

首页warmup收尾最多等待2秒，在正常检测/跟踪前结束。相机检测阶段事件唤醒现有watchdog；正常帧不增加轮询频率或图像计算。中断旧会话时省去完整历史显示采样/排序汇总，必要计数和错误保留。UNIFIED_READY/RECOVERY_READY日志显示实际新门限。

## 验证与限制

440项主机检查通过，包括329项核心回归、30项显示/owner、36项预算/计时/预热、45项相机/UI/服务actor/源码保持检查。部分历史断言按2秒冷却及用户提供的定制V18更新；测试从独立目录执行，历史证据不覆盖。八图Windows NCNN验证通过，模型未训练。

实际相机C++函数经Windows原生编译，在模拟V4L2驱动下25项检查通过，涵盖持有lease拒绝重配、同fd切档、新旧帧代次隔离、无效帧、错误清理。正常camera_next/release函数体与V18逐字相同。CPU采集/手动prepare及图像/显示算法保持检查通过。

本机ARM交叉工具链对最小源文件也报FileNotFound，未将ARM语法检查记为通过。安装本的CPU检查在Linux上编译/加载真实相机辅助库并验证ABI3102和reconfigure ABI1，尚不打开设备。真实USB驱动重配、持续相机/HDMI输出与板端帧率仍需实机验收。

9轮交替独立进程控制流程对比：同样开启混合的V18→21，正常AUTO约18.846→19.230微秒/帧，增加0.384微秒；AI跟踪约15.813→16.058微秒，增加0.245微秒。开启混合相对纯AUTO的控制层约额外12.493微秒。测量使用实际控制器及同一相机/图像前端替身，是控制层开销，不是整机FPS。不能把这些数值说成板端帧率已保证不降。

1.5/2.8秒是触发门限，整个恢复还包括线程收尾、推理和当前帧验证。大运动/长遮挡可能更早进入恢复。相机复用只减少设备和流程等待，不消除AI推理或跨档位重新稳定时间。

## 安装与验收

停止旧程序，完整独立安装本版；保留用户提供的V18。依次运行安装本的完整安装、AI图片自检和reuse21_cpu_check.py；全部通过后进入打印的TARGET目录，重启内核运行p11_start.ipynb。

分别在480P/600P测试反复手动/refind/AI、推理中重选、主页3秒内返回与超时、拍照/重拍、连续切档及回退、连续换书/白布/平板视频/运动遮挡。核对HOT_SWITCH_CAMERA_REUSED、CAMERA_STREAM_RECONFIGURE_END/FALLBACK、AI_REQUEST_DISCARD_END、AI_BUDGET_STABLE_REFUND及2秒冷却日志。

同场景比较稳定跟踪段CORR/HDMI帧率和帧间隔，不用含搜索等待的整段均值或冻结输出替代。上传新run-result.log便于判断实际USB重配命中和耗时。
