# 第17版：进度条收尾与手动参考跟踪

仅修改界面进度生命周期和真正手动入口的实时跟踪。普通自动、AI找角后的跟踪、显式AI锁/丢失回自动、3秒/5秒冷却保持16版；模型、C++、FPGA、相机、PL队列和CMA配置不变。

## 进度条

显式AI入口使用独立反馈类型，等待本次真实输出；进入等待、冷却或错误时，提交当前实时画面后结束加载条，底栏继续显示真实状态。标角入口仍等待手动标注界面。结束/取消后卸载临时处理器，并使相关画布缓存失效，后续所有者重绘清除残留条。正常帧只进行一次空回调检查，没有新的图像算法。

## 手动跟踪

手动入口单独启用v117_manual_reference，AI仍走16版旧PersistentManualTracker。输入仍是用户确认的物理外角，后续保持参考点到当前点的关联，避免只把上一帧四角作为不断变化的依据。

优先使用覆盖目标的稳定物理边界点；四个分布充分的边界点可支撑整体运动，常规纹理点最多保留24个，必要时原分布兜底仍不超过32。边界缺少可用点时采用分布充分的目标内部纹理，保护白底白书的可跟随性。动态平板用例不依赖内屏内容。

现有同一套双向LK结果先尝试严格小残差的相似运动；需要真实透视变化时才运行原RANSAC单应估计。没有增加第二套光流。四角由参考平面整体变换产生，倾斜仍允许真实透视。

静止判断维持6400个样本预算，集中到实际目标特征周围，不再由大片平坦背景/书面主导。静止复用期间保留与光流点匹配的灰度/原生金字塔参考，只更新独立的采样状态；成功跟踪后成套提交参考和点。

初始化保存64×64参考图，约每1秒及补点时做一次外环归一化相关核对。核对明确不匹配时不提交候选四角；无纹理时标记证据不足，不伪造模板证明。原有物理边缘恢复继续沿用，因此极低纹理且外边界不可见的场景仍有信息限制。

手动短暂失效接入明确标记的当前帧延续，最长1秒，估计帧不续期；已有明确出画、运动过大判据立即清除旧几何。保持同目标恢复，不自动选另一目标。原图继续实时，人工快照标角的静态流程不变。

## 验证与帧率

主机9轮交替测试，真实OpenCV双向LK路径：静止用例总跟踪耗时下降约10.5%，平移约31.6%，透视约31.7%。合成已知几何用例最大角点误差：平移约10.61→0.20像素，透视约2.54→0.57像素。这是受控合成图结果，不等于真实视频精度。

正常显示/提交独立9轮整轮耗时中位约2428.2→2474.5微秒（+1.91%）；逐帧中位约2396.9→2389.1微秒（-0.33%），逐帧P90约2843.3→2900.7微秒。绝对差异在约0.06毫秒以内，存在主机波动，未以此声称板端帧率保证。另保留与测试并行时的受干扰记录，未用它作为独立性能验收。Windows无法执行PYNQ原生LK内核；测试执行了真实OpenCV等效路径，并验证单次原生事务/成功后promote接口协议。板端实际原生LK与相机/HDMI帧率仍需用户验收，未声称主机耗时就是板端FPS。

参考跟踪测试包含平移、真实透视、白底同色书、有纹理背景上的目标运动、变化视频、参考失败不提交和有限延续；进度测试覆盖实际UI分类、输出、等待、错误、取消、旧代次和清除残留。完整数量和源文件哈希见manual17_validation.json。

在相同场景下对比16和17的有效矫正FPS与DISP，延续不计入可靠矫正。重点测试手动静止、移动倾斜、短遮挡恢复、白布白书与平板视频；自动/AI仍作为16版行为对照。旧continuity/pic56/paired报告仅供追溯。
