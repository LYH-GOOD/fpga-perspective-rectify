# 平板物理外框训练版 physical-20261026-4

本版以用户认可的 fast-20261026-3（实时路径源于 flowfix 第一版）为基线，目标是**平板外壳的物理四角，包括黑边**。本版没有把内屏视频矩形作为训练目标。普通自动矫正、相机、HDMI、原手动跟踪、C++、bit/hwh 均保留基线字节。

## 已完成的训练

训练目录：`D:\p11_ai_training\tablet_pic4_20261026`。

- `manifest.json`：293 张，训练 203、验证 36、测试 54。PIC4 的 26 张同一设备/同一拍摄组全部只在训练集；旧的 12 张“内屏”标签从本次训练剔除，原始文件保留。书本按原物理对象分组的验证和测试集保留。
- `run_physical_v4/best.pt`：从 PIC3 实际部署检查点微调，RTX 4060 Laptop，24 轮，固定随机种子 751，实际训练 98.81 秒，选择第 24 轮。书本验证集参与模型选择，书本测试集未参与训练或轮次选择。
- PIC4 物理四角平均误差：旧 9.01 px，新 1.45 px；平均误差≤10 px 且最差角≤20 px 的样本数由 17/26 到 26/26。这是**训练集拟合**，不能称未见平板准确率。

## 对播放视频、重拍和抖动的修改

原问题不仅是模型：内屏取点会被视频内容带动，旧帧 AI 结果交到当前帧时也会因为视频变化被 FB 拒绝。新权重把目标统一到物理外壳；交接与实时阶段优先验证外壳的四条物理边缘。

`v104_physical_tracking.py` 在 320 宽灰度图上每条边取 24 个剖面，一次 `cv2.remap` 批量读取四条边，用有方向的明暗变化区分黑色外壳和外部桌面，并一次批量拟合。每帧没有模型推理、光流、逐边 SVD 或倾角枚举。它不同于之前板端耗时约 106 ms 的 screen-2 搜索实现。

每条边都需要足够多、分布充分、残差合格的当前像素证据；四角通过原几何验证后才提交。细小抖动使用 0.65 源像素死区，大位移直接跟随，低速移动相对累计测量位置仍会越过死区，不会永久冻结。正常局部跟随范围有限；快速大幅移动、严重反光、手遮住外框、黑色外壳置于深色背景，都可能拒绝，不能声称所有环境都已解决。

平板一时遮挡后继续在原位置附近测量。原 1.5 秒有限保留期不延长，超过后显示 LOST；不会用旧 H 无限充当成功，也不会自动跳到视频中另一个矩形。不能证实该物理边缘配置的其他平面沿用原 FB 路径。普通自动与用户主动手动入口保留基线。

## 验证与帧率口径

21 项 AI 入口/取消/重试/资源所有权/真实交接回归和 8 项物理跟踪回归通过。包括视频随机变化、平移、旋转缩放、目标消失、保留期到期、局部恢复，以及 PIC4 开头三张真实内容变化照片。26 张照片的新 NCNN 候选均能建立物理外框证据。此组照片也用于开发，不能作为独立测试；连续实拍视频尚未提供。

主机单线程、相同外壳种子与相同 99 帧输入下，原 FB 跟踪中位数约 2.79 ms，新批量测量约 1.76 ms，P95 约 4.20 → 3.00 ms；两者均成功 99/99。这是 PC CPU 跟踪耗时，**不是 PYNQ 的实时输出帧率**。模型结构不增大，普通自动路径不变；当前尚未板测，所以不能保证板端 FPS 已经达标。用户选择自行上板测试。

安装包内 `benchmark_physical_tracking.ipynb` 可比较板端原 FB 与新测量的记录图像 CPU 耗时，不打开相机、HDMI、PL；它也不能替代实际输出帧率。实际帧率应看同一 HDMI 模式、同一目标尺寸、相同播放内容下的 `run-result.log` 中 `display_outputs/elapsed_s`，同时比较 CURRENT/MANUAL 与 HELD/LOST；只看瞬时数字可能把丢失后回退误认为提速。

## 安装与上板测试

1. 把本次完整 ZIP 与 `install_ai_physical_full_20261026_4.ipynb` 放在板端 Jupyter 同一目录。停止旧程序，运行安装 notebook 全部单元。它校验 ZIP 和每个文件，安装到新目录，不覆盖旧版；支持微信自动加 `(1)` 的 ZIP 文件名。
2. 等待四图 ARM CPU 自检通过。进入新目录，重启内核，运行 `p11_start.ipynb`。不需要设置旧 screen-2 环境变量，不要混拷单个 Python 文件或旧模型。
3. 同一视频连续播放：平板/相机固定 30 秒，重复进 AI 三次；再缓慢平移、旋转 30 秒；再短暂遮挡外框并放开。首次推理期间保持物理位置基本静止，视频可以继续播放。
4. 与 fast-3 在相同模式各跑同样时长。保存两份 `run-result.log`，关注 AI 候选到接受是否还反复重拍、是否出现 `physical_four_edges_batched`、跟踪是否为 `PHYSICAL_EDGE_FAST`、实际输出帧率是否下降，以及 LOST/HELD 比例。若出现耗时或证据拒绝，再运行可选性能 notebook，提供其 JSON。

模型不在实时循环内反复运行；原 CMA 内存保护没有关闭，冷启动仍可能影响点击后的等待时间。本版解决的是物理目标与视频干扰机制，并未把等待时间和稳态 FPS 混为一项指标。
