# 第22版：480P/600P切档进度条

以完整第21版为基础，合入附件第18版(1)的进度条体验，并修正首帧完成、停流绘制及取消清理。

## 本次修改

- 使用小型、只读的UI状态快照。进度由绘制时的单调时钟计算，1秒走到95%，之后缓进到最多99%；这是等待提示，非硬件完成比例，不显示精确百分比。正常跟踪不分配进度字典，不运行动画计时器。
- 有相机帧时进度随正常画面绘制；停流无帧时，现有HDMI owner最多10Hz显示明确的切档界面，不回放旧相机帧，不新增显示线程。排队的新画面优先，合成/提交在显示锁外进行。普通实时画面的空画布拦截保留。
- 设备参数生效后，卡片显示“等待新档位画面”。对应请求/会话、正确输入尺寸、重配后新鲜帧真正提交成功，进度才到满；下一张正常画面自动擦除卡片。原图和只矫正页面的有效结果均能完成，不强制复制原图。
- 空桌面不必找到四角即可结束切档。随后仍按21版的自动/AI策略寻找目标；切档时不叠加第二个导航进度条。
- 返回首页、手动/其他会话请求、应用退出清理对应进度状态。重复应用不会重新计时；旧请求/旧画面不能结束新请求。设备准备成功后即使用户已离开，也记录真实已生效档位，避免下次按钮文字错误。
- 设备重配失败继续走21版回滚。参数已经成功但在现有3秒首帧超时内仍无画面，结束动画并显示“新画面尚未到达，可重新找四角或返回”；保留真实设备档位，不把无图说成切档完成。
- 新增3张缓存中文卡片，运行前加载；按钮、480P/600P参数、显示分辨率和图像布局保留。

## 保留的21版行为

自动转AI开启；丢失确认1.2秒、实际自动无候选搜索1.5秒、同轮有效候选验证上限2.8秒；恢复冷却每次2秒。短暂失效最多1秒用可信几何矫正当前像素。AI成功稳定3秒后只退本次请求名额，失败限制保留。AI入口锁、真正手动权限、同目标恢复策略保持。

同档位相机复用、AI进程复用、原设备跨档重配/失败重开保持。检测、跟踪、模型权重、采集C++、PL bit/hwh和像素转换/缩放代码保持21版。实际480P输入640×480@30，600P输入800×600@15；这不是矫正输出FPS。
