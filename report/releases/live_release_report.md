# 第12版：固定左右实时输出

基于第11版独立迭代，不训练模型。自动操作固定比较布局：左侧实时相机，右侧只显示有效矫正像素。取消自动暂存、居中和整页进度图。运动丢失、遮挡、换书和 AI 等待使用同一显示规则。重新取得有效四角并完成实际矫正后，直接显示新结果。

## 实现与边界

- 移除活动链路的 DisplayHold 快照及同阶段不提交逻辑；失效结果清除右侧旧图，不把 HELD、MANUAL_HELD 或 frozen_output 当作有效输出。
- 比较布局不再根据有无输出更换位置或整页清屏。保留原有显式手动选点、截图、相册与用户主动选择的显示布局。
- 正常准备帧复用已有不可变原图快照。准备线程停顿时，相机采集线程在 MMAP 帧交给消费者之前制作普通内存预览；准备线程随后取得同一帧时复用这份快照。
- 相机仍只有原来的消费者，预览不调用 camera.take；HDMI 仍只有原来的输出线程。两个显示槽位及三个 P1 输出槽保持不变。预览使用单个最新值，不积压帧、不增加 CMA 分配。
- 正常矫正提交优先。独立补发只在至少两个显示周期没有新提交时介入，默认补发上限约15FPS；原相机与 HDMI 的30FPS配置不变。采集线程不承担显示转换或 AI 推理。
- 正常帧间隔内右侧按原有输出节奏更新；收到失效状态立即清除，准备线程完全阻塞时，结果超过0.5秒不再显示。此时间只控制显示过期，不改变内部同目标恢复。
- 左右来自不同时刻时，日志分别记录 input_camera_sequence、result_camera_sequence、input_capture_ready_at、input_capture_age_ms；same_frame 为 false，旧四角不叠到新原图上。独立预览不会重复计入有效矫正帧率。
- 保留第11版原子的 AI/自动交接、旧看门狗计时清理和检测阶段协作取消。新目标仍先自动，失败后有限次 AI，预算与冷却保持不变。真正手动的跟踪、恢复和权限保持不变，仅原图快照出口复用新函数。

## 验证

210项主机检查，覆盖实际输出 offer/合成函数、真实输出槽引用计数、实际采集函数及 HDMI 输出循环的设备替身测试。连续100次有效/HELD/丢失交替不耗尽输出槽；准备线程被阻塞时左侧仍刷新；正常30FPS模拟准备没有新增采集备份。实际手动跟踪等价、换书恢复、AI 交接、计时和取消回归保留。

主机配对测量（不代表 PYNQ 帧率）：640×480 原图快照与发布中位数24.185→26.447微秒；实际 Python 合成函数、主机转换替身1815.967→1797.792微秒；健康控制路径17.790→18.426微秒。模型、跟踪原生内核与 FPGA 配对文件不变。主机没有发现明显正常路径开销增加，但板端调度、带宽和 HDMI 需要实测，不能据此保证板端FPS绝不下降。

## 安装与验收

解压 upload_all 合集，把里面的程序 ZIP 与匹配的安装 notebook 一起上传 Jupyter。停止旧程序，运行安装本全部单元；四图AI与CPU自检通过后进入打印的新目录，重启内核，运行 p11_start.ipynb。安装保留旧版，避免将单个新文件覆盖旧目录。

同一光线、目标、背景和比较布局下与第11版比较有效 CORR 和 DISP。测试连续换书20次、目标横移、相机移动、短遮挡、完全移出再放回，以及白布上的视频平板。重点观察：左侧持续变化且位置不变；右侧失效清除、有效直接恢复；不再出现 DISPLAY_HOLD_CAPTURED/COMMITTED；独立预览不虚增 CORR。板端相机/HDMI/FPS由用户验收。
