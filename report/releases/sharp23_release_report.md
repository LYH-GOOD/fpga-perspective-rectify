# 第23版：PL锐化与左侧图像设置

## 本次合入

软件基于完整第22版；使用交接包 `vivado/bits/experiment_bypass` 的 system.bit 与 system.hwh 原始成对文件，未重建bit流。system.bit SHA256 为 fcc5865a598891d79c374f5a0414f69328e2d784ad7adf9159601e3d1739c92d；HWH SHA256 为 3a5055f15e283d780c22f4756630591d0c251df5a106745cea02081be6247ae0。

左下入口改为“图像设置”，左侧面板分“分辨率 / 锐化”两个页签。锐化提供关闭、1.0、1.5、2.0、3.0、4.0预设与可拖动滑条（0–4、步长0.1）。滑条只更新待应用值；点击“应用锐化”后由现有PL处理线程在下一完整帧边界读取一次配置，全帧使用同一配置。不重开相机、不重建HDMI、不加CPU滤镜。

界面区分当前值、待应用值、等待输出、PL已启用、分块旁路及尺寸旁路。只有对应请求的矫正结果真正提交HDMI后才确认状态；原图或旧结果不能冒充生效。首次安装默认关闭；用户应用值在匹配输出提交后异步保存到p11_sharp_settings.json。恢复保存值也必须有真实结果才能确认。

## 当前bit流的能力边界

锐化只位于矫正结果链路，左侧原图、中文UI不做锐化。按HWH实际地址访问 axis_bypass_0=0x40001000、axis_sharp_0=0x40030000，不采用源文件注释中的错误绝对地址。初始化核对成对SHA/CRC、HWH参数与实际流连接、bypass版本。

提供的5×5锐化核行缓存宽度为512，且按每个DMA包独立处理。因此仅单块、输出宽度≤512的结果启用PL锐化；多块或过宽输出明确走硬件旁路，继续正常矫正。不能将旁路显示成锐化成功，也不以CPU补偿影响帧率。480P/600P为相机输入档位，与上述矫正输出宽度、分块数不是一回事。

锐化寄存器W/H、Q8系数只在变化时写入；每个启用包启动一次，并利用原S2MM完成点检查核状态，无新增等待循环。正式关闭/分块旁路时不访问锐化核；DMA和remap原有配置/缓存/数值处理保留。

## 保留行为与帧率

自动转AI开启；丢失确认1.2秒、实际自动无候选搜索1.5秒、有效候选验证同轮上限2.8秒、每次恢复冷却2秒。短暂失效最多1秒使用可信四角矫正当前画面，估计帧不续命。手动、AI入口权限、同目标恢复、相机/AI进程复用、480P/600P切档和首帧进度完成机制保留。模型、检测和跟踪代码、native采集与像素转换保持22版。

图像设置使用启动时加载的中文图集，不增加实时字体绘制、整幅相机复制或缩放。拖动最多20Hz更新小状态，不强行额外提交HDMI；正常闭合栏位使用缓存小图。软件没有新增逐帧滤波线程或画面缓冲。

506项主机检查全部通过，含新增30项锐化/MMIO协议、逐帧配置一致性、旁路、触摸拖动/取消/过期事件、实际合成器与源码范围检查，以及原有自动/AI、手动、连续显示、相机复用、进度条回归。旧scope断言仅放行已授权硬件/UI改动，由新scope检查补足。八图Windows NCNN验证通过。CPU检查核对新配对文件、Q8参数与模拟MMIO请求/提交链路，不打开FPGA。

九张1280×720实际合成器截图已检查，USB/PL/HDMI使用替身。9轮交替独立进程对照，显示批次耗时相对22版 -0.05%，帧耗时中位数 +0.67%，P90 +1.00%。主机测试不能据此保证板端FPS；新bit流的吞吐量和实际锐化效果仍待板端验收。

Vivado MCP的Tcl/GUI会话均在就绪前退出；静态编译工具也不可用。因此本次未完成RTL仿真、综合、时序分析或板端测试。未把交接包历史结果当成本次测试。保留原始提供的bit/HWH，不声称已证明生成源与bit完全一致。

## 安装与验收

程序ZIP与新安装Notebook上传同一目录，停止旧程序后执行全部安装/AI图片自检/CPU检查。进入打印的TARGET目录，重启内核运行p11_start.ipynb。不覆盖22版。

板端先在锐化关闭时对照22版相同场景的CORR/HDMI帧率、帧间隔；再用单块输出对比0/1.0/1.5/2.0，观察SHARP_SETTING_REQUESTED、SHARP_ROUTE_SELECTED、SHARP_FRAME_SUBMITTED。需要见PL已启用才能判断实际锐化。多块应显示分块旁路。切档、换书、运动、手动及AI模式都需保留实时左图。

提供可选 sharp23_board_check.py：停止UI后，在本目录终端运行 `python3 sharp23_board_check.py --board`。它会下载配对bit流并执行DMA合成图检查，不打开相机/HDMI；比较关闭一致性与1/1.5/4的5×5/Q8内部像素参考，产生sharp23_board_check.json。边界像素和实际帧率不在此脚本验收范围内。运行后重启内核再启动UI。此脚本本次未上板执行。

当前报告及验证为sharp23_release_report.md / sharp23_validation.json；其余旧版报告只作历史资料。
