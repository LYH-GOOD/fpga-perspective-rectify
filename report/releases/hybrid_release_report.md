# hybrid6 自动优先与 AI 接管交付说明（2026-10-27）

本版从 trackfix5 完整包单独迭代，保留原包和安装目录。目标是自动优先、失败后有限度使用 AI，同时明确显示当前矫正来源。硬件、AI 权重、物理边缘内核和正常自动跟踪算法没有更换。平板目标仍为机身物理外缘，包含黑色边框。

## 实际切换规则

| 当前状态 | 条件 | 行为 |
| --- | --- | --- |
| 自动寻找 | 相机正常出帧，进入后 3 秒仍没有第一张有效矫正输出 | 停止原自动 CPU 工作，再提交一次 AI |
| 自动已输出 | 第一张有效输出后满 1 秒，滚动最近 1 秒有效输出少于 4 张，包含 0 张 | 请求转 AI；等旧工作安全退出再推理 |
| AI 已有候选 | 与当前帧对齐，并经过至少 3 个不同帧、跨度不少于 0.20 秒的跟踪确认 | 等第一张矫正像素实际完成后显示 AI 跟踪成功 |
| AI 没有找到目标或候选确认失败 | 当前帧没有可靠候选 | 显示等待目标，按 5、10、20 秒退避，之后最长每 20 秒一次 |
| 等待中场景发生稳定变化 | 2Hz 的小图变化检测连续确认，并且本次失败期间尚未提前唤醒 | 最多提前唤醒一次；这只触发找目标，不作为四角正确的证据 |
| AI 跟踪持续失效 | 相机正常出帧，连续 3 秒没有当前有效输出 | 退出旧跟踪，再走 AI 确认流程 |
| 相机断流或报错 | 没有新相机帧 | 保留相机错误处理，不能把它误诊为需要 AI |
| 真正手动模式 | 用户选定四角 | 保持手动目标，不被自动/AI 接管 |

滚动窗口使用已完成输出的时间戳；窗口恰好 4 张不触发。启动和跟踪阶段各自计时，不把启动尚未满一秒的低计数作为低帧率。监控每 0.1 秒检查一次，真正交接还要等待正在执行的工作释放资源，不能保证在阈值那一毫秒完成切换。

有效输出要求 CURRENT、相机序号递增、非冻结图片，而且在提供采集时间时完成输出距采集不超过 0.5 秒。HELD、LOST、重复显示、固定旧坐标、旧队列结果不算自动有效帧。AI 静止快路径最多沿用最近真实跟踪证据 0.20 秒；它不能续期证据。缺少当前证据时仅有限保留，超过 1.5 秒不再矫正旧位置。

空白场景仍可能由自动转到 AI，这是正常的排查动作。AI 也找不到时显示原始画面及等待状态，不伪造四角、不反复往返自动和 AI，也不连续重复推理。AI 运行错误与未找到目标分别显示和记录。

## 界面与日志

底部显示“自动 / AI / 手动”来源，以及寻找、推理、候选确认、跟踪、暂时保留、丢失或等待。AI 找到后使用轻量跟踪更新四角，来源仍显示 AI，方便判断是哪个入口产生的矫正。

- `CORR(valid)`：最近 1 秒实际完成的有效矫正张数。手动固定状态会单独标识，不代表重新测量了四角。
- `DISP`：现有的显示提交速率，与有效矫正速率分开。
- `HYBRID_TRIGGER`：达到 3 秒无输出或低帧率条件时记录。
- `HYBRID_SWITCH`：旧 CPU 工作退出、真正转入 AI 时记录。
- `HYBRID_AI_REQUEST`、`HYBRID_WAIT_TARGET`、`HYBRID_AI_ACCEPTED`：分别记录推理、退避、第一张已完成 AI 矫正输出。

## 帧率控制及证据限制

正常自动路径继续使用原来的 Frontend、PrepareQueue、检测、跟踪、规划和 PL 矫正。前两者与 trackfix5 的语法树完全一致；相机、HDMI 的所有权和单槽队列保留。新增控制只读少量状态和完成时间戳；该路径没有新增模型调用、整帧复制或边缘审计。中文提示一次加载为缓存小图，逐帧只覆盖底部小区域。

主机 7 轮、每轮 30000 次的控制路径测试，测得额外开销约 **9.13 微秒/帧**，折合 30fps 时单核时间的约 **0.0274%**。测试包括委托准备、完成回调和释放，不包括真实相机、像素计算、PL、ARM 或 HDMI。该数字只证明主机上的控制开销很小，不能换算成板端帧率，也不能承诺绝对零损耗。

自动失败后先退出原工作才运行 AI，不让两套重计算并发抢 CPU。同一时刻最多一次推理，不堆积请求；AI 使用当前相机流的一次独立快照，不重启相机。已成功跟踪后不逐帧运行模型。白布上低对比边缘、遮挡和视频内屏特征仍可能导致失败，本版没有重新训练模型或添加逐帧重检测，因此不能承诺所有背景均能识别。

模型推理和当前帧确认有实际耗时，AI 搜索期间不能承诺矫正输出保持原跟踪帧率。界面会如实显示搜索阶段，不能用保留旧四角来维持虚假的高 `CORR(valid)`。

101 项主机检查通过：切换策略 18、控制器 19、AI 流程 21、跟踪 23、状态界面 17、真实主循环函数配合假设备的所有权测试 3。覆盖 3 秒边界、恰好 4 帧、0 帧、旧队列、空场景退避、候选确认、实际像素完成后接管、固定四角不冒充当前跟踪、退出取消和单次释放。跟踪测试包括已有 26 张 PIC4 和合成明暗背景/移动/遮挡案例。界面按原生 1280×720 输出预览核对。模型和 ARM NCNN 运行库、硬件配对、原生内核均校验保持不变。

以上为主机测试；本次没有连接开发板，没有测量本版板端 FPS，也没有执行板端相机、触摸、HDMI 或 ARM 自检。安装 notebook 会在你的板上运行原四图 AI 自检和新增 CPU 策略/内核自检；这些自检也不能替代真实画面的帧率测试。

## 安装与板端验收

1. 停止旧程序，把 `p11_rgb_v9_ai_hybrid_20261027_6.zip` 与 `install_ai_hybrid_full_20261027_6.ipynb` 放在 Jupyter 同一目录。
2. 运行安装 notebook 的全部单元。安装器校验完整包，自动建立新目录，保留旧目录；微信追加 `(1)` 的文件名也可识别。
3. 四图 AI 和 CPU 自检通过后，进入打印出的新目录，重启内核，运行其中的 `p11_start.ipynb`。
4. 首先同一对象、同一背景、光照、距离、输出大小，固定相机，分别设置启动参数 `hybrid_auto_ai=False` 与 `True` 各测 30 秒稳定自动跟踪，再测移动。关闭参数仅关闭自动入口的 AI 接管；显式点击 AI 仍可使用。比较稳定段有效矫正速率、原有跟踪/DMA耗时及 P95，而不是包含启动搜索、AI 推理或空白阶段的整段平均。
5. 默认 `True`，分别测试：启动空场景、放入书/平板、白布背景、木纹背景、移走目标、换书、短遮挡，以及手动模式拖动四角。确认状态提示和日志对应，手动不会自行退回自动。

如稳定自动段帧率下降，请保留两次 `run-result.log`；首先依据 `HYBRID_TRIGGER/SWITCH` 判断是否进入 AI，再比较原始跟踪和 DMA 耗时。按用户选择，由用户完成板端验收，本包没有把未测数据写成“帧率不下降”。

本次未实现曲面展开，也未重新训练；曲面矫正是独立需求，不能靠四角透视解决。
