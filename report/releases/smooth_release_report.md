# 第11版：暂留画面、有效新图一次替换

基于第10版startfix1完整包独立迭代，旧包保留。模型、手动及物理边缘跟踪内核、原生C++内核、相机驱动和FPGA配对文件不变。主要修改显示交接、跟踪器安装状态和检测取消。

## 改动

1. **暂留旧图，准备好再换**：首次丢失时从已有完成输出获取一次普通内存快照，暂留原布局。后台依旧先自动、必要时AI；新四角通过当前帧核验、跟踪器安装并实际矫正出有效新图后，才由原HDMI所有者一次提交替换。候选框、旧轮次结果或未核验的HELD图不能替换。
2. **不再每帧重绘暂留图**：同一等待阶段只提交一次，阶段变化才更新小状态。没有每帧全屏备份、缩放或动画；暂留快照不持有相机映射、CMA或VDMA画布。
3. **暂留有边界**：最多8秒，确认空场景即清除旧书；失败冷却不反复续期。无可安全保留的旧有效图时，沿用实时原图和原进度条。真正手动、相册、快照和页面切换保持原权限。
4. **修复误回退**：新跟踪器安装期间阻止看门狗读取半完成状态，AI/自动安装完成后一起发布新的起始时间与状态，清除旧一轮超时。新首帧期限从本次安装完成后计时，有效FPS仍只由真实完成输出计数。
5. **缩短检测退场**：自动检测使用既有候选、颜色、轮廓和核验阶段的检查点响应取消，停止后续尝试。既有检测顺序、阈值和当前四边核验不变；不强杀线程、不提前释放工作空间，不抢占正在执行的单次原生调用。日志新增ACQUIRE_RETIRED以实测退出等待。

## 状态与帧率

暂留状态显示“暂留画面·准备中”，OUT PAUSED、CORR(valid) 0；它不是有效新矫正输出，不增加有效输出数。真实HDMI提交和暂留事件另有日志，物理屏幕刷新率不冒充算法帧率。

正常跟踪不增加图像检测、AI推理、全屏备份或新的像素转换。新增快照发生在切换事件，完成后立刻释放临时硬件输出引用；普通内存快照保证新DMA输出槽仍可使用。主机成对控制逻辑开销见smooth_steady_benchmark.json，不能替代板端相机、HDMI与FPS测试。

本版保持新目标稳定出现先自动，以及原搜索/低帧率/持续丢失/AI预算和冷却策略。没有把恢复搜索时限统一压短，也没有在正常跟踪期间并行预跑AI。实际恢复总时间仍包含检测与AI计算，不能保证所有目标都瞬间恢复。

## 验证

212项主机检查通过：交接期间插入看门狗、AI与自动原子安装、首帧新期限、取消上下文隔离及真实检测工作线程安全退出；真实offer/合成器/输出槽引用检查，包括连续50次交接、暂留无CMA引用、旧帧/旧代拒绝、8秒超时、空场景、页面变化、内存不足和显示提交失败；保留既有白底/木纹换书、播放视频、真正手动、手动跟踪一致性、模型交接及策略检查。

启动目录查找的14项检查已执行，支持嵌套、改名和安装后缀，仍按第11版精确身份识别。打包后另执行新安装目录中的首个启动代码单元及完整包校验，不只检查语法。

主机使用假相机/假HDMI画布验证合成和所有权；原生边缘内核执行于Windows主机。没有声称已经完成ARM相机视频、真实HDMI无闪烁或板端FPS验收。

## 安装

在电脑解压upload_all合集，把里面的程序ZIP和安装notebook一起上传到Jupyter同一目录；不要手动反复解压程序ZIP。停止旧程序，运行安装本全部单元。四图AI和CPU自检通过后，进入打印的新目录，重启内核，运行p11_start.ipynb。

建议优先测试：连续换书20次、短遮挡、同目标移动、空场景再入、白布上的播放视频平板；观察暂留是否一次替换、新图准备好后是否仍误回退。比较帧率时使用同目标、背景、相机参数、光线和布局，分别看有效CORR、显示DISP、暂留时长及ACQUIRE_RETIRED耗时。
