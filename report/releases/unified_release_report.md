# unified8：AI 只给初始四角，后续复用手动跟踪（2026-10-27）

本版基于已交付 hybrid6 单独建立完整发布目录。落实用户确认的方案：首次进入先自动；自动启动修复后仍无法有效输出，才由 AI 给初始四角；对齐当前帧后，使用与手动选角完全相同的 ManualFrontend、PersistentManualTracker、参数及同目标恢复。新增“确认空场景后，下一次目标稳定出现先走 AI”。未采用先前讨论的“AI 接原自动跟踪器”，未重新训练或修改 PL。

## 为什么这样改

hybrid6 的 AI 路径强制优先使用物理边缘跟踪，而手动路径优先特征点跟踪；两者也有不同的失效恢复。新日志中 17 次 AI 自动重找，16 次发生在物理边缘路径，1 次在 FB 路径。AI 连续 3 秒无有效输出就重跑模型，形成反复重建跟踪的循环。

另有 5 次自动启动，初次源图检测全部第一次通过，却都在约 3 秒触发切换，未完成自动接管。相机稳定已占约 1.5～2 秒，计时起点及超时交接顺序不合理。详细原始证据保存在独立 diagnosis_hybrid_auto_20261027 目录，本版不把“源图检测通过”当作后续一定能输出的保证。

## 本版实际流程

| 场景 | 行为 |
| --- | --- |
| 首次正常进入 | 原自动寻找、跟踪和矫正 |
| 自动启动无有效结果 | 相机稳定后计算搜索 3 秒；已找到候选给一次最多 2 秒宽限，单次在途检测也有有限完成机会；控制器启动总上限 8 秒 |
| 自动结果刚完成，旧超时也到了 | 优先取已经发布的自动结果；首次有效输出可撤销旧超时请求 |
| 自动已成功输出但长期低速 | 第一张有效输出满 1 秒后检查滚动窗口；最近 1 秒不足 4 张且低速状态持续 1 秒，才申请 AI；恰好 4 张不触发 |
| AI 找到四角 | 保留原当前帧对齐，随后构造默认手动前端；不强制物理边缘优先，不使用额外 0.2 秒静止证据限制 |
| AI 定位后的短暂失效 | 原手动跟踪器保留目标、按原策略恢复；旧四角保留上限仍为 1.5 秒 |
| 同一目标持续无法恢复 | 显示丢失、原始画面，继续原同目标恢复；不因“3 秒没输出”再次调用 AI |
| AI 未找到目标或发生运行错误 | 显示等待／错误；同一目标轮次不定时重试 |
| 确认当前画面已经没有目标 | 停止旧目标跟踪，显示“空场景·再入先AI” |
| 空场景后再次稳定出现目标 | 新建目标轮次，先调用一次 AI，再交给同一手动跟踪策略；不先运行完整自动检测 |
| 用户点击重新找四角或重新进入 AI | 显式建立新一轮定位，可再次尝试 |
| 用户真正手动选角 | 保留用户选定目标和原入口控制，不被自动场景规则接管 |

8 秒为整个控制器启动上限，因此遇到极慢稳定或检测时会以总上限为准，不承诺在每个阶段都用满各自预算。触发检查每 0.1 秒一次；真正切换仍需安全退出正在运行的 CPU 工作，实际交接耗时可能超过阈值。

## “空场景后先 AI”的判定

跟踪丢失、一次没找到轮廓都不等于没有目标。新增检测只用于启动新一轮 AI，不直接提供矫正四角或当前证据。

检查使用最大边约 160 像素的小图，最高 2Hz。在等待、丢失或未测量的固定／静止保持阶段检查；已经测得当前几何的正常自动和手动帧跳过图像探测。

空场景需至少 4 个不同序号的负样本，跨度不少于 1.5 秒，并结合背景相似、旧目标区域变化等证据；存在明确矩形时不确认空场景。之后需要至少 3 个稳定的正样本、跨度不少于 1 秒，才能启动下一次 AI。已保存空场景时，还可以使用相对空背景的稳定局部变化作为出现线索。一次重新出现只产生一个请求，不能由同一轮失败持续重试。

合成白布、木纹、视频画面、短遮挡及重复帧检查通过。该检查是保守的图像启发式，不具备语义上的绝对可靠性：低对比白物体、复杂背景、长期相似遮挡仍可能漏判或误判。未确认空场景时保持丢失／同目标恢复，不凭模型失败强行重置；可点击重新找四角。平板内屏仍不作为训练或矫正目标，使用的 AI 权重继续标注机身物理外缘，包含黑色边框。

## 手动跟踪一致性的验证

实际执行两条入口的真实 ManualFrontend 和 PersistentManualTracker，只替换硬件规划器，不使用假的跟踪器。使用相同初始帧、四角、相机序列和计时，对照静止、移动、遮挡恢复、无纹理固定四角四组场景。四角、手动源状态、跟踪种类、证明标记、失败原因和输出计划均一致。

公共自动主循环需要统一计数，AI 手动后端的 MANUAL／MANUAL_HELD 分别映射到 CURRENT／HELD；原始状态保存在 manual_source_state。这个映射不改变实际跟踪、阈值、坐标或恢复过程。固定四角单独显示 OUT FIXED 和 CORR(output)，不能冒充当前重新测得的几何。

保留的 ManualFrontend 类、原自动 Frontend 和 PrepareQueue 与 hybrid6 语法树一致；底层手动、物理边缘跟踪模块和 C++ 内核保持原字节。

## 来源显示及日志

界面显示“自动定位／AI定位／手动”与跟踪阶段。AI 成功后显示“AI定位·手动策略跟踪”；固定四角、暂时保留、丢失、空场景分别标记。CORR(valid) 是完成的新鲜不同帧矫正输出计数，DISP 为显示提交速率；固定四角和单帧输出使用 CORR(output) 明示。

关键日志：UNIFIED_AUTO_PHASE、UNIFIED_AUTO_ACCEPTED、UNIFIED_TRIGGER、UNIFIED_SWITCH_CANCELLED、UNIFIED_AI_BEGIN、UNIFIED_AI_REQUEST、UNIFIED_MANUAL_SEEDED、UNIFIED_AI_ACCEPTED、UNIFIED_TARGET_ABSENT、UNIFIED_TARGET_RETURNED、UNIFIED_EMPTY_WAIT、UNIFIED_WAIT_TARGET。UNIFIED_AI_ACCEPTED 只在第一张实际矫正像素完成后记录。

逐帧附带 corner_source、tracking_engine、target_cycle_state。额外存在检查耗时计入 presence_check_s 和准备耗时，避免隐藏等待阶段的开销。

## 帧率与验证范围

正常自动路径保留原算法、规划、相机和 HDMI 所有权、单槽队列、硬件配对。AI 完成初始定位后不逐帧推理，两套重检测不并发；中文状态为一次加载的小图缓存，正常测量帧没有新增模型、全图检测或整帧复制。

主机 7 轮、每轮 30000 帧的控制路径基准，新增开销约 10 微秒／帧；小图到期检查约 0.7 毫秒／次、最高每秒两次，检查仅用于上文所列阶段。这些数值来自 Windows，不能换算为 ARM 帧率或承诺绝对零下降，精确结果见 unified_validation.json。

主机回归共 130 项：控制器 26、空场景与返回 16、真实手动一致性 4、AI 流程 21、已有跟踪 23、真实主循环配假设备的所有权 3、计数策略 18、界面 19。包括真实存在检查接入控制器后的重新出现先 AI，以及视频内容变化不重复推理。UI 使用原生 1280×720 预览检查。模型、ARM NCNN .so、原生内核、system.bit/hwh 逐文件校验保持不变。

没有连接开发板，尚未执行本版 ARM 相机、触摸、HDMI 或实时 FPS 验收。安装 notebook 在板上运行四图 AI 自检、CPU 策略／原生内核自检和空场景状态自检；这些仍不能替代实时测试。

## 安装及板端验收

1. 将 p11_rgb_v9_ai_unified_20261027_8.zip 与 install_ai_unified_full_20261027_8.ipynb 上传到 Jupyter 同一目录，先停止旧程序，再运行安装 notebook 全部单元。
2. 自检通过后进入打印出的新目录，重启内核，运行 p11_start.ipynb。安装器保留旧目录，支持微信追加 (1) 的 ZIP 文件名。
3. 同一场景分别测试手动选角与 AI 定位，每段稳定 30 秒，再移动、短遮挡，比较稳定段输出 FPS 和跟踪耗时；不能把启动搜索和 AI 推理的整段平均当作稳态帧率。
4. 测试先自动是否能完成接管；移走书／平板，等待“空场景”，再放入目标，确认出现 UNIFIED_TARGET_RETURNED 后先产生 UNIFIED_AI_REQUEST，最后进入手动策略跟踪。
5. 同一目标不动、播放视频、放白布和木纹背景，确认没有定时重复 UNIFIED_AI_REQUEST。看不到边界时允许丢失和等待，不能一直使用过期四角。检测不到语义上的空场景时，点击重新找四角。
6. p11_start.ipynb 的 hybrid_auto_ai=False 可作原自动路径对照；关闭后也关闭该入口的自动 AI 救援和空场景重新出现规则。显式 AI 按钮仍可使用统一手动策略。

本版不包含曲面展开，不重新训练、不更换硬件。未发布的 AUTO 接管7仅是之前讨论中的独立实现，不属于本次交付。
