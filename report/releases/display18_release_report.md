# 第18版：预览与连续显示

以已交付17版为基础。沿用现有AI模型、自动和手动跟踪算法、模式锁/丢失恢复策略、3秒/5秒恢复冷却、进度条，以及原相机、P1后端和FPGA文件。

## 本版行为

- 同一相机热复用和实时布局交接保留最新的只读原图快照；新目标只重置几何。不同相机不继承原图。错误代次的预览不再抹去本来有效的原图。
- 实时页已有图像后，不再让“两侧都无输入”的画布覆盖当前显示；有新原图则立即显示原图。没有新原图时不重复提交旧图冒充实时帧，记录空提交拦截。
- 150～250毫秒的自适应计时仅表示产出停顿，实际输入仍受0.5秒新鲜度约束。同目标软失效仍允许最多1秒可信几何延续。
- 准备线程超过原自适应期限、后端正在等待时，由原来的PL owner使用已证明的映射/分块处理最新相机快照。没有第二个硬件线程、camera.take、AI推理、光流或额外图像复制。正常结果已经就绪时直接处理正常结果。
- 延续不刷新四角确认时间，不计入CURRENT有效定位帧率。确认目标离开/新目标、硬运动失败、取消、退回首页或1秒到期后不继续用旧位置。执行过程中目标代次变化时也不提交旧结果。
- 新增DISPLAY_LIVE_EVENT、DISPLAY_CONTINUITY_BEGIN/END，覆盖以前未记录的index=-1预览提交。仅状态变化时记录少量画布像素与元数据；不逐帧扫描整张图，也不以黑色亮度决定是否丢弃图像。

## 验证与帧率

359项主机检查通过，包括30项新增显示/owner/队列/取消/资源检查；100轮延续与恢复未耗尽输出槽。原有八图Windows NCNN、CPU原生边缘与手动参考跟踪检查通过。ARM上的真实LK和相机/HDMI未在本机执行。

9轮交替、独立进程的正常显示对比：合成/交接整批每帧约2.875→2.923毫秒，差0.0475毫秒；逐帧中位2.751→2.791毫秒，差0.0403毫秒；就绪队列约增加0.077微秒。测试使用CPU转换替身及模拟HDMI，不能换算成板端FPS。前一轮对比也保留在外层display18目录。

正常路径的跟踪、模型、C++和PL没有变化；正常帧不会触发新增后端补帧。准备线程真实停顿时，补帧使用原来闲置的后端；恰逢正常结果到达，可能需要等当前硬件事务完成。无法在没有板测时承诺任何场景绝对零帧率变化。

## 板上验收

在相同目标、姿态和布局下对比17/18：静止、持续移动、遮挡后恢复、连续换三次书、白布上的白书和平板视频。分别看有效矫正CORR、HDMI有效提交、恢复时间和两侧同时闪黑。

如果仍闪黑，保留新的run-result.log；若按钮文字也消失，需要结合物理输出检查。当前日志没有足够证据锁定之前所有整屏闪黑的来源，本版修复已明确的软件空提交/交接路径，并为剩余问题补证据。

使用完整安装包独立安装，保留17版目录。板上CPU检查使用display18_cpu_check.py，旧的短计时断言已同步修正。历史版本报告保留供追溯，以本报告及display18_validation.json为本次结果。
