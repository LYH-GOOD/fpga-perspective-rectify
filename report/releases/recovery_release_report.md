# recovery9：丢失先自动重找，AI交接失败可恢复（2026-10-27）

本版从已交付 unified8 单独迭代，不覆盖旧包。解决新日志中“目标已重新入镜，AI也有候选，但交接失败后一直等待”的恢复死路。稳定跟踪继续使用原自动路径或共享手动跟踪；不重新训练模型、不改动PL和底层跟踪内核。

## 主要修改

| 情况 | 本版行为 |
| --- | --- |
| 首次普通进入 | 先自动，保留第8版稳定后3秒搜索、候选宽限和启动总上限8秒 |
| 短暂失效 | 先由原跟踪器同目标恢复，旧四角仍按原1.5秒期限失效 |
| 持续约2秒没有新鲜有效输出 | 退出旧CPU前端，复用当前相机流，进入自动重新找角 |
| 自动恢复没有结果 | 搜索约3秒；在途检测可有限完成，已有候选一次最多1秒宽限；本轮上限4.5秒，之后尝试AI新截图定位 |
| AI有候选但对齐失败／AI没有找到／运行错误 | 转入自动恢复或有界冷却，不能把已经存在的目标锁在WAIT_TARGET |
| 恢复自动找到并通过原检查 | 原自动跟踪器继续工作；不必再等模型 |
| AI定位和交接成功 | 继续使用默认ManualFrontend/PersistentManualTracker及同目标恢复，仍不改成AI四角交给原自动跟踪器 |
| 确认空场景后重新出现目标 | 保留先AI；失败后允许自动恢复。若自动AI预算耗尽，可先自动检查，不空等模型配额 |
| 真正手动选角 | 保留用户控制，不自动转入新恢复流程 |

重计算只由相机生产线程串行切换。先安全退出旧检测／跟踪，再创建新工作或提交AI；相机、HDMI、硬件矫正所有者不重新开启。每个新跟踪器的计数从自己的第1帧开始，搜索耗时不会直接老化新锚点。

时限用于发出请求，检查周期约0.1秒；已有原生调用或工作器还要安全退出，实际切换耗时可能超过标称阈值。不能通过忽略清理或继续使用旧四角来追求表面上的即时切换。

## 不锁死，也不快速循环

同一次持续失败最多两轮快速自动恢复；每轮自动失败后可进入一次AI。两轮仍不成功，进入恢复冷却，按5、10、20秒退避，之后每20秒自动复查。恢复不再要求必须先经历ABSENT→RETURNED；目标保持PRESENT或UNKNOWN也能继续尝试。

自动触发的AI请求使用进程内共享滚动预算：一分钟最多3次，稳定成功不会清空全局预算。预算耗尽时仍可低频自动检查。用户显式点击实时AI的第一次请求单独处理，后续自动救援受预算约束。

候选边界使用已有2Hz小图检查提供独立的稳定线索，不只在空场景状态生效。新的稳定外框可以在一次持续失败中提前唤醒一次自动恢复；视频内屏内容变化不能反复重置这个提前唤醒许可。稳定输出约3秒，或确认新的目标轮次，才清零退避级别并恢复提前唤醒许可；冷却到期允许下一轮有界自动复查，不清空全局AI预算。

冷却限制的是模型和重搜索频率，不延长过期几何的寿命。看不到边界时显示原始画面或明确的固定／保留状态，不能通过一直刷新旧结果伪造有效帧率。

## 同时修复AI入场交接

第8版虽然统一了后续手动跟踪，入场仍物理边缘优先。本版先用与手动一致的PersistentManualTracker做当前帧交接；失败时最多进行一次物理外缘后备验证。FB一致性、几何、位移、物理四边门槛没有降低。两条路径都拒绝时，记录两个原因并进入恢复，不强行使用旧AI四角。

模型推理有实际耗时，目标持续运动、角点偏差、低对比边缘仍可能导致交接失败；本版提供后续恢复机会，不保证所有候选一定可用。每次AI重试取当前新帧，不重复推理同一冻结快照。平板仍以机身物理外缘、包含黑色边框为目标。

直接点击实时AI也进入同一个恢复控制器，绕过旧的阻塞式实时选择流程。因此主动点AI和自动转AI都能恢复；用户仍可通过原按钮切换到手动。静态截图AI保留原固定图选择方式，不涉及实时自动恢复。

## 界面及日志

新增“自动重新找角”“对齐失败转自动”“恢复冷却”，冷却显示RETRY剩余秒数，不再把交接失败统一显示成等待入镜。保留定位来源、跟踪方式、CORR与DISP分开的提示。真空场景仍显示“空场景·再入先AI”。

新增RECOVERY_READY、RECOVERY_TRANSITION、RECOVERY_TRIGGER、RECOVERY_AUTO_BEGIN、RECOVERY_AI_REJECTED、RECOVERY_COOLDOWN、RECOVERY_EARLY_WAKE、RECOVERY_CANCELLED、RECOVERY_STABLE、RECOVERY_EXPLICIT_AI_ENTRY。原UNIFIED_AI_REQUEST／AI_ACCEPTED和目标离开／返回事件继续保留。逐帧只在需要时增加恢复轮数、AI失败来源和冷却剩余时间字段，正常路径避免重复计算。

AI_ACCEPTED只在实际完成第一张矫正像素后记录，模型返回candidate并不等于矫正成功。旧异步结果按epoch隔离。相机断流走原错误处理，不用AI救援掩盖设备问题。

没有连接开发板，未测本版实时FPS、ARM恢复、相机、触摸或HDMI。安装CPU自检会在板上执行原生内核和状态／预算检查，但不能替代实时验收。低对比物体与相似遮挡仍可能影响空场景判定和四角正确性，不能仅凭无图像日志保证视觉效果。

## 安装与验收

1. 将p11_rgb_v9_ai_recovery_20261027_9.zip与install_ai_recovery_full_20261027_9.ipynb上传到Jupyter同一目录，先停止旧程序，再运行安装notebook全部单元。
2. 四图AI和CPU自检通过后，进入打印的新目录，重启内核，运行p11_start.ipynb；安装器保留旧目录并支持微信追加(1)的文件名。
3. 优先复测上次换书：直接换、先移走等空场景再放入，各测一遍。AI交接失败后应出现自动恢复或冷却，而不是目标一直PRESENT却等待入镜几十秒。
4. 测试直接点AI的失败恢复、短遮挡、持续遮挡、视频平板、白布／木纹。真正手动选角应继续保持用户控制。
5. 同一书本、光照、距离和输出大小，分别在第8版和第9版稳定跟踪30秒，再测试移动；比较稳定段CORR、DISP、跟踪／DMA耗时及P95。启动／恢复期间有效输出可能为0，不能与稳定段混算后声称帧率不变。
6. 保留run-result.log，重点查看RECOVERY_AI_REJECTED后的RECOVERY_AUTO_BEGIN、冷却期限、后续AI_REQUEST和真实AI_ACCEPTED。hybrid_auto_ai=False仍可比较普通入口的原自动路径；显式AI入口保留本版恢复功能。
