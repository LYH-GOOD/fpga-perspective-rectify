# 4.4 AMD ROSS 智能体套件的使用心得与优化建议

对 AMD ROSS 套件，我们用了两种方式验证它的功能性：一是自 2026 年 10 月 2 日起把它接入本项目的日常工具链，在真实开发里边用边看；二是在最终交付版本敲定之后，用一次“盲重建”专门试它的独立作业能力。

**日常开发中的便利。** 一是会话常驻，设计软件的进程在对话结束后不会退出，连续调试时不必反复冷启动，这一条省得最多。二是长命令返回运行中状态后自动交接，可以并行做别的事，不像图形界面那样整块占住操作者。三是没有图形界面也能拿到全部现场，告警原文、端口清单与模块锁定状态都直接返回，排查时不必截图对照。可复现的量化记录有两条：启动软件并跑通第一条脚本用时 14.2 秒，手工开界面约需 3 到 5 分钟；打开已交付工程读取实现报告用时 77 秒。

**日常开发中的缺点。** 需要说明的是，它省的是敲命令和等界面的时间，设计决策与参数取舍仍由人完成。工具行为上另有四处不便：低版本打开高版本工程时返回只读，要自己想到先另存为低版本；工程引用的 IP 仓库缺失时，报错要到综合阶段才暴露，而且表现为顶层被自动替换成别的模块，排查成本很高；长命令只有运行中与成功两种状态、没有进度，而综合实现动辄几十分钟；重复启动构建时不检查是否已有构建在跑，会和自己撞上。

**盲重建的做法。** 把本项目的 PL 源文件、IP 仓库与约束连同任务书一并交给它，全程禁止读取原工程。为确认“盲”是真的，事后逐条复核了它全部的读文件记录，553 条路径无一落在原工程上。

**盲重建凸显的优势。** 它独立跑通了综合、实现与写比特流，产出一份 389 行重建报告，含各时钟的时序裕量与全设计文件的哈希表。产物上板验证：加载 15.16 秒，13 个 IP 全部识别，读 AXI DMA 的寄存器能返回正确值（0x00011003）；主时钟的时序裕量为 +0.248 ns（83.333 MHz），另一时钟域为 +0.643 ns，设计规则检查无报错。过程一共跑了六轮，全程没有人插手：前三轮是多个子模块的独立综合任务并发时互相冲突，它把并行任务数由 8 改为 1 后通过；第四轮一个子任务的综合进程崩溃，它只重跑那一个、其余成果保留；第五轮布线阶段静默退出，无报错也无崩溃记录，它靠缺失的阶段标记判断这一步没跑完，复位后重跑。

**盲重建暴露的弊端。** 它的验证只覆盖“设计能不能造出来”，可用性低：文件生成、时序收敛、规则检查无报错，这三条讲的是工程完成度，没有一条回答“造出来能不能用”。整轮重建里没有把一帧图像送进流水线，不核对输出，所以比特流在功能上仍是未检验的。另一次试验把这一点暴露得更彻底：让它从零写一个透视校正 IP，综合、实现、比特流都能写出，仿真也通过，但上板后 4 KB 地址空间里 1024 个寄存器全部为 0——总线握手能完成，主控不会挂死，但读数据不被寄存器表驱动、未生成写使能。它的仿真覆盖了三个算法核，恰恰没覆盖寄存器的读写时序，因为没有人要求它覆盖。

**补齐判据之后，它的输出可用性提高了。** 第一轮把验收条件改成“每个寄存器写进去要原样读回”，它二十分钟就定位到读数据寄存器被两处逻辑同时驱动——这个缺陷仿真看不见——修好后 4 KB 地址空间的非零项由 0 变为 896。第二轮要求“一帧要传得动”，它查出 DMA 单次传输的长度位宽沿用了默认值，单次上限只有 16,383 字节而一帧需要 1,228,800 字节，改成更大位宽后重建；同轮它自己报出下一个阻断点：流水线每输出一行就发一个行结束标志，而 DMA 的简单模式会把任何一个这样的标志当成本帧结束，并且不报错。第三轮据此修改了三处帧结束标志的生成逻辑，其中一处不在任务书里、位于旁路分支，是它自己找出来的；配套的静态检查对旧代码报 3 处失败、对新代码报 0 处。第三轮的比特流因本机综合工具环境故障未能重建，它没有因此写“已完成”的报告。

**结论。** 两次验证放在一起，可以说得更准确：ROSS 的“跑对”能力取决于有没有一条能判红的判据。给弱判据，它把活干完但功能一个没验；给强判据，它二十分钟就能挖到只有综合语义才暴露的缺陷，并顺手把自己的验收标尺也改对。所以本项目的用法是——人负责定义“什么叫对”，它负责把“对”做出来。

**优化建议。** 七条均来自实际踩到的点：

| # | 问题 | 建议 |
|---|---|---|
| 1 | 低版本打开高版本工程时返回只读 | 打开阶段就提示可另存为低版本 |
| 2 | IP 仓库缺失要到综合才暴露，且表现为顶层被自动替换成别的模块 | 打开工程时即检查 IP 仓库是否齐全 |
| 3 | 长命令只有运行中与成功两态、没有进度 | 显示设计软件自身的进度百分比 |
| 4 | 交付前没有功能门禁 | 比特流出包前必须有寄存器读写回环与端到端数据通路（送一帧进去、核对输出）两类证据，缺了不许写通过 |
| 5 | 生成的寄存器从设备没有协议级测试 | 自动附一份测试：遍历地址读默认值、写图案再读回、检查应答信号是否真的拉起来 |
| 6 | 通过标准混用，“全部通过”会被读成“东西成了” | 拆成时序、加载、功能三档；“未做功能验证”这类限制写在开头 |
| 7 | 重复启动构建时不检查是否已有构建在跑 | 启动前检查进程或状态文件，加一道互斥 |
